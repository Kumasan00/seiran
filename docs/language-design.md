# Seiran 言語設計原則

Seiran の言語（`.sei` ソースの構文・コマンド・環境・設定ファイルの役割分担）を設計するときの
規範を定める。新コマンド・新環境・新オプション・新スタイルフィールドの設計判断は、
必ずこの文書の目的と原則に照らして行う。

構成は「前提（スコープ） → 目的（3 つ） → 原則（10 個、各原則がどの目的に仕えるか明記） →
判断事例集」。原則は目的の手段であり、原則と欲しい機能が衝突したときは
例外を継ぎ足すのではなく、目的に照らして原則側の改訂も検討する。

## 1. 前提（スコープ）

Seiran は **LaTeX の主要機能を組み込みで提供する汎用組版言語**である。

- 機能はコアが持つ。マクロ・パッケージ機構で機能を後付けする設計にしない
- LaTeX 互換層は作らない。TikZ のような埋め込みプログラミング言語も採用しない
- ユーザ拡張は将来の `\define` メタコマンド + `.seiran` ファイルに限定する
  （固定引数の新コマンド定義。プラグイン機構・スタイル継承は持たない）
- `\documentclass` 相当のクラス概念は導入しない

原則はすべてこの前提の内側で効く。「その機能を作るか」はこの前提が決め、
「作るならどう作るか」を以下の目的と原則が決める。

## 2. 目的

**読み手にも書き手にも曖昧さのない組版言語。** 3 つに分解する。

- **G1. 一意に読める** — ソースのどの箇所も、離れた場所の定義・実行状態・カテゴリコードに
  依存せず、字面だけで構造が一意に決まる。
- **G2. 効果が閉じる** — あらゆる指定の効果範囲が構文上で閉じており、書いた場所から見える。
  「いつ終わるか不明」な状態を作らない。
- **G3. 内容が見た目から独立** — ソースは内容のみ。同じソースに別の style.toml を当てれば、
  同じ内容の別の見た目が出る。

「同じ結果を得る書き方は一つ」（`$$` と `\[` を併存させない等）は独立の目的とせず、
各原則の適合例として扱う。第 2 の書き方かどうかは名前が何を名指すかで判定する。名前が意味（内容）を名指す
コマンドは、同じ出力になる別の書き方があっても第 2 の書き方ではない（`\Re` と `\mathfraktur{R}`、`\code` と `\mono`、
演算子名）。退けるのは、字や見た目を呼ぶだけの名前が別の書き方と同じ結果になるときだけ（`\lparen` と `(`、`\vert` と `|`）。
記号コマンドは非 ASCII の字を ASCII で書く綴りで、字と 1 対 1 に対応する（#959）ので、直接入力の字に対する第 2 の
書き方には数えない（`\alpha` と α、`\Vert` と ‖）。直接書ける ASCII の字には名前を置かない。

## 3. 原則

### P1. トークン規則は固定（G1）

字句規則は言語が固定し、ユーザは変更できない。カテゴリコードは存在しない。
コメントは `//`（`%` は将来の剰余演算子に予約）。特殊文字はエスケープ必須で、エスケープできるのも特殊文字（構文文字と、区切りを持つ区間の直下の区切り）だけ。
文脈によって役割が変わる文字を作らない。

コードブロック（verbatim、#447）は「固定構文で入る固定の字句モード」であり、
ユーザによる字句規則の変更ではない。P1 と両立する。

### P2. 引数構文（G1）

引数を取る構文の必須引数は `{}` で明示し、個数・順序は構文ごとに固定する。
対象はコマンドに限らず、数式の上付き `^` / 下付き `_` も含む。
`\section Title` は不可で `\section{Title}` のみ、`$x^2$` は不可で `$x^{2}$` のみ。
コマンド名は英数字始まり・英数字続きで、英数字以外の文字で終端する。

### P3. オプション引数は名前付きのみ（G1）

オプションは `[key=value, ...]` の名前付きのみで、コマンド名／環境名の直後に 1 組だけ置ける。
順序自由・キー重複はエラー。bool 値は `key` 単独（`=true` 省略）を認める。
値の中の `,` / `=` は P1 のエスケープ `\,` / `\=` で書く（区切りは構造トークンとしての `,` `=` だけ）。
引用符 `"` は値の境界ではなく普通の文字。
LaTeX の `\parbox[c][3cm]` のような位置依存オプションは作らない。

値は宣言済みスキーマ（String / Bool / Number / Length / Color）で検証する。
Length / Color の字面はソースの引数と style.toml / config.toml で同一（書式は 1 つで、値域はキーごとのスキーマが
上に重ねる）。
実例: `\image[width=5cm, dpi=300]`、
equation 環境の `[label=eq1, numbered=false]`、`\cell[span=2]`、`\row[rule_above]`、
theorem 環境の `[title=...]`。

### P4. `{}` の意味は 2 つだけ（G1）

`{}` は「引数の境界」（コマンド・`^` / `_` など引数を取る構文）と「数式内のグループ化」のみ。
数式外の裸の `{...}` は構文エラーとする。数式内では `$a{+}b$` のようにグループとして使える。
「数式外 / 数式内」は `$` の入れ子ではなく、その位置をどの読み方で読むかを指す（本文と数式内の `\text` の引数はテキストとして読む位置）。

### P5. 数式モード境界の単純化（G1）

インライン数式は `$...$` のみ。ディスプレイ数式は数式環境（equation / align 等）のみ。
`$$...$$` と `\[...\]` は不採用（同じ結果への書き方を増やさない）。

### P6. 未知は拒否（G1）

未知のコマンド・環境・数式コマンド・カウンタ名・オプションキーは、静かに無視したり
フォールバックしたりせずエラーにする。環境本体に書ける要素は許可リスト方式。
設定ファイルも `deny_unknown_fields` で同じ方針を貫く。

推測で処理を続けないことで「書いたものがどう解釈されたか」の曖昧さを消す。

### P7. 効果範囲の構文的閉包（G2）

コマンド・環境の効果が及ぶ範囲は、構文だけから一意に決まらなければならない。
範囲は次のいずれかで閉じる。

- (a) 自身の引数（例: `\bold{...}`）
- (b) 環境本体（例: `\begin{quote}...\end{quote}`）
- (c) 構造上固定の単位（例: align の行末 `\notag` ＝その行のみ・置ける位置も一意）

ソースを読み進めないと終端が分からない指定は作らない。非適合例: LaTeX の `\bfseries`。

宣言型か引数型かは手段の選択にすぎない。新コマンドを宣言型にしたい場合は
「(a)(b)(c) のどれで閉じるか・置ける位置が一意か」を判定し、閉じないなら引数型か環境にする。

### P8. マクロ置換なし（G1, G2）

テキスト置換機構は提供しない（`\newcommand` 相当なし）。将来の `\define` は
「固定引数の新コマンド定義」であり置換ではなく、P2 / P3 の引数規則に従う。
`{}` 引数は自己区切りなので、定義を知らなくても構文解析は常に一意に決まる。

### P9. プログラミング機能なし（G1, G2）

計算・条件分岐・ループは提供しない。ソースの評価結果が入力以外に依存しない。

### P10. 内容と見た目の分離 — 線引きは「種類 vs 個」（G3）

- **種類・文書全体の既定はソースに書けない。** 「見出し全部」「表キャプション全部」
  「本文フォント」のような種類（クラス）単位の見た目デフォルトは style.toml、
  物理・実体・メタデータは config.toml に置く。ソースに書けば文書全体へ開いた効果になり
  P7 とも矛盾する。プリアンブル相当の禁止・クラス概念の不採用はここから導出される
- **個別要素の設定はソースに書ける。** 効果がそのコマンド・環境 1 つに閉じる限り、
  列挙値（`table[columns=left center right]`）も具体的な数値（`\image[width=5cm]`）も可。
  オプション引数（P3）がその受け皿
- **両方要るものは「style.toml / config.toml に既定 + ソースで個別上書き」** の型にする。
  実例: 画像 DPI（config.toml `[image].max_dpi` + `\image[dpi=...]`）。

**判定テスト**: 「これは 1 要素の設定か、種類の既定か？」
個 → ソースのオプション。種類 → style.toml（見た目）/ config.toml（物理・実体）。

**不変条件**: 同じソース + 別の style.toml ＝ 同じ内容・同じ個別指定のまま、
種類既定だけが変わる。style.toml へ新フィールドを足すときの判断基準
「同じ本文 + 同じ用紙で style.toml だけ差し替えて見た目を変えられる」はこの不変条件の言い換え。

**基準と機能判断の分離**: P10 が決めるのは「その指定をどこに置くか」だけ。
「そのオプションを提供するか」は機能ごとの判断で、まず種類既定（style.toml）で
足りないかを検討してから個別オプションを設ける。

### P1 トークン規則は固定

#### エラー厳格化（2026-06）— P1, P6

括弧等の特殊文字はエスケープ必須（P1）、未知の数式コマンドはエラー・環境本体は許可リスト方式（P6）。
個別の確定判断: 裸の `[` はテキスト・数式ともエラー（stray `]` が既にエラーだったことと対称。区間表記は
`\[0,1\]` と書く。LaTeX 互換に読み替えるレンダリング案は不採用）。閉じない `$` はエラーで通貨表記は `\$` 必須。
未知の数式コマンドをリテラル表示へ暗黙に戻す経路は持たない（P6: 静かなフォールバックを残さない）。インライン文脈（見出しタイトル・キャプション・装飾引数）でも未知コマンド・ブロック要素・環境・
空行はエラー。数式外の `_` `^` `&` は本文と同じプレーンテキスト扱い（エラーではない。`&` を構造として読むのは
table 環境本体のセル区切りだけ）。`label=` の重複は
エラー。コマンドの必須引数は外側文脈のパースモードを継承し（`\frac{x^{2}}{y}` の `^` を構造化するため）、
任意引数 `[...]` は常に Text モード（key=value 用）。

#### 引数のパースモード解決順 — レジストリ宣言が外側文脈の継承に優先する（2026-08、#447）— P1

「エラー厳格化（2026-06）」が定めた「コマンドの必須引数は外側文脈のパースモードを継承／任意引数は常に
Text」に第 3 のケースを足す。verbatim を宣言したコマンドの必須引数は、外側が Text でも Math でも
レジストリの宣言が勝って生読みになる（数式内の `\url{https://…}` も `//` がコメントにならず、数式の語彙に無い
未知のコマンドとして拒否される）。
宣言できるのは frontend のレジストリだけで、ユーザは変更できず、将来の `\define` も verbatim 引数モードを
宣言できない（P1 ガード: 字句規則をユーザに開かない）。継承のほうを既定に残すのは、`\frac{x^{2}}{y}` の `^` を
構造化するという 2026-06 の理由がそのまま生きているため。

数式内の `\text` の必須引数も同じ順序で、外側が Math でもレジストリの宣言（テキストとして読む）が勝つ（#977）。
`_` `^` を字、裸の `{...}` を構文エラーとして読む。宣言できるのは frontend の数式の語彙だけで、将来の `\define` は
この読み方も宣言できない（P1 ガードは verbatim と同じ）。

#### verbatim の終端文字を選ぶ根拠は「その文字が対象言語の文法で元々不正か」（2026-08、#453）— P1, P2

verbatim はエスケープを持たず終端規則 1 個だけで成立するので、終端に選んだ文字は対象言語で書けなくなる。
`\url` / `\href` のリンク先で `}` を終端に選べたのは、`{` `}` が RFC 3986 の reserved にも unreserved にも
属さず URI 中では元々パーセントエンコードが必須だから ＝ 採用コストがゼロだったため。この論拠は転用可否を
判定する道具であって、verbatim 一般の許可証ではない。実際、任意引数値の verbatim 化（`\href[url=...]` を
生読みする案）はこの判定で落ちた — 終端候補の `,` は RFC 3986 の sub-delim、`]` は IPv6 リテラルホストで
合法なので、どちらを選んでもその文字を含む URL が言語内で書けなくなる。加えてブレースの場合と違い、
オプション値には「ブロック環境へ逃がす」ような言語内の逃げ道が無い。

#### コマンド呼び出しの直後の空白の帰属（2026-09、#516）— P1, G1

パーサは次の引数を探して空白・改行・コメントを跨ぐが、跨いだトリビアがコマンド呼び出しに属するのは
**引数が見つかったときだけ**。必須引数を 1 つ以上読んだ後に跨いで何も見つからなかった空白は本文へ返し、
コマンドが無い場合と同じ語間のアキになる（`\bold{x} y` は `x y`）。字面に書いた空白が組版に出るという G1 の読み方をコマンドの
前後で揃えるためで、LaTeX が空白を食うのも `\LaTeX foo` のような波括弧を伴わない制御綴りの後だけで
`}` の後ろではない。

必須引数を 1 つも読まなかった場合はコマンドが空白を食う（`\noindent 本文` / `\pagebreak` /
数式記号 `\alpha b`）。この位置の空白はコマンド名の終端を示す区切りであって語間ではなく、返してしまうと
`\noindent` の直後＝段落の先頭に空白が入る。コマンド名と引数の間（`\bold {x}`）・引数どうしの間
（`\href{u} {t}`）も引数探索が成功した側なので食う — 引数の境界は `{}` が示すので（P2）、
その手前の空白に語間の意味は無い。

#### 結合文字はトークンを切らない（2026-10、#955）— P1, P2, P6, G1

結合文字（直前の字と書記素クラスタを切らない字 — Grapheme_Cluster_Break が Extend / SpacingMark / ZWJ）は、
直前の字と同じトークンに入る。ソースの字面（エディタの表示）で結合文字が付いて見える字と、字句解析が結合文字を
付ける字を一致させるため（G1）。各位置の扱いはこの規則 1 つから決まる:

- テキストの字・エスケープした字（`x̂` `\&̂`）: その字と 1 字
- コマンド名（`\alphâ`）: 結合文字は名前の最後の英字に付いて名前の一部になる。英数字だけの名前（P2）に当たらないので、
  未知のコマンドとして拒否する（P6）。エディタには `\alph` と `â` に見えており、α に付くという読みは字面に無い。
  記号に付けるにはアクセントコマンド（`\hat{\alpha}`）を使う
- `=` `,`: 構文になるのは任意引数の中だけで、本文・数式では字なので、結合文字が付いた形はテキストの字として読む
  （`=` + U+0338 は ≠ の正準分解で、数式では ≠ と同じ関係演算子の 1 字 — 「数式に直接書いた記号」（#959））
- そのほかの構文文字（`\` `{` `}` `[` `]` `$` `_` `^` `&` と `\\`）: 結合文字が付いた形は字面がもう構文文字ではなく、
  エスケープしていないので字でもない（P1）ため、構文エラーにする。`_` `^` `&` は本文では字だが、字句解析はモードを
  持たず、文脈で役割が変わる文字を作らない（P1）ので同じ扱いにする。グループに付けるには `\hat{x}` を使う
- 空白・改行の後: 空白は別トークンのままで、結合文字は次のテキストの先頭になる。本文では空白を基底に結合文字だけを
  見せる Unicode の書き方として通す。数式は空白を組版に出さず付く字が無いので、診断エラーにする
- コメント `//` の本文は字句規則の外なので、`//` の直後の結合文字はコメントの一部になる

2 案を落とした:

- (a) **恒久不採用** 結合文字を直前の HIR ノード（記号コマンドが出す字・グループ・構文文字）に付ける。`\alphâ` を α̂ に
  するのは、字面に無い字へ付ける読みなので G1 に反する。グループにはフォントの結合で結合文字を載せられず、結合文字から
  アクセントへの対応表を作れば `\hat{x}` の第 2 の綴りになる（`\code` と `\mono` の判定と同型）。記号コマンド・
  構文文字・グループの 3 通りの結合機構も要る
- (b) **恒久不採用** 直前のテキスト以外に付いた結合文字を一律に診断エラーにする。`=` + U+0338 は字面どおり ≠ で、
  正準等価な綴りを拒否する理由が無い。また `\alphâ` を「付く字が無い」と診断すると、エディタで `a` に付いて見えている
  結合文字について、字面と食い違う説明になる

「1 文字」を書記素クラスタで定義する字句概念は #486 (a) で恒久不採用にした。ただしあれは、スクリプトの引数を字数で閉じる
規則への不採用である。この規則は字数を数えず、トークンの境界を結合文字で切らないだけなので衝突しない。

**見送り**: 本文で付く字を持たない結合文字（段落の先頭など）の診断。再検討のトリガーは、本文で結合文字が字に付かずに
組まれる報告が出たとき。

#### エスケープできるのは構文文字と、区切りを持つ区間の直下の区切りだけ（2026-10、#967）— P1, G1, P6

エスケープは、その位置で構文になる字を字に戻すためだけにある。構文にならない字のエスケープは同じ字の第 2 の書き方
（G1。#87 で `\lparen` を直接入力の第 2 の書き方として退けたのと同じ論法）なので、構文エラーにする。LaTeX の記号名（数式の `\,` `\:` `\;` `\!`、本文の `\%` `\-` `\'`）が
黙って字として組まれる罠は、この規則の帰結として塞がる。受け付ける字は #955 の構文文字の 2 層をそのまま継ぐ:

- **どこでも**: `{` `}` `[` `]` `$` `_` `^` `&` と `/`。`_` `^` `&` は本文では字だが、字句解析はモードを持たないので
  #955 と同じく位置によらずエスケープできる（本文の `\_` が形式上の第 2 の書き方になるのは P1 の均一さを優先して許す）。
  `/` はモードを持たないコメント `//` を字として並べるために要る（数式で `/ /` が同じ出力になるのは #86 の帰結で、
  規則を分ける理由にならない）。`\` 自身は `\\` が改行なので入らない（逆斜線は `\backslash`）
- **区切りを持つ区間の直下だけ**: 任意引数 `[...]` の直下の `,` `=`、`\cite` の引数の直下の `,`（#687 / #731）。
  区切りで割るのは直下の要素だけなので、入れ子の引数・グループの中の `\,` `\=`（`[title=\bold{a\,b}]`）は拒否する。
  `\cite` の引数が `,` 区切りであることは、verbatim と同じく evaluator のレジストリが引数モードとして宣言する

判定は `\` に続く字で行い、付いた結合文字は見ない（`\&̂` は可、`\%̂` は不可）。verbatim の中はトークン化しないので
対象外。#687 の「構造文字はその位置で文法が意味を与えなければ自分自身に
戻る」（裸の字を受け付ける寛容側）と対になる厳格側の規則で、合わせて「字の書き方は位置ごとに 1 つ」になる。

- **恒久不採用** 現状維持（記号名は字になると書くだけ）— 第 2 の書き方が残る（G1）
- **恒久不採用** `\,` `\:` `\;` `\!` だけの専用診断・字ごとの案内 — #687 が退けた移行ガードと同型で原則から導けず、
  列挙を広げると LaTeX 互換層になる（§1）。一般の規則が `\|` `\-` `\'` も同じ診断で捕まえる
- **恒久不採用** 位置ごとに可否を決める規則（その位置で構文になる字だけ）— 本文の段落の `\&` と table セルの `\&` で
  可否が割れ、字句がモードを持たない（#955）ことと食い違う
- **見送り** `\%`。今は `%` が字なので拒否する。再検討トリガーは剰余演算子（P1 の予約）を構文として導入するとき — そのとき
  どこでもの層へ足すのは非破壊
- **見送り** LaTeX のアクセント `\^o`・イタリック補正 `\/` が字として見えること（`^` `/` はエスケープできる字なので通る）。
  再検討トリガーは誤用の報告

### P2 引数構文

#### 数式スクリプトの内容は `{...}` のみ（2026-08、#486）— P2, P4, G1

上付き `^` / 下付き `_` の内容は波括弧グループに限り、`$x^2$` も `$x^\alpha$` も構文エラーにする。
裸の内容を許すと範囲が字句のトークン境界で決まり、`$x^2=y$` は `x²=y`、`$x^2+y$` は `x^(2+y)` と、
後続の区切り文字の種類でスコープが変わってしまう（`=` `,` は構造文字でトークンが切れるが `+` `-` `(` は
切れない）。字面から範囲が読めないので G1 に反する。採用形は P2「必須引数は `{}` で明示」の直接適用で、
#453 の判定テスト（その値なしでハンドラが成功しうるか）も「`$x^$` は既にエラー ＝ 必須引数」を返す。
P2 の対象はコマンドに限らず引数を取る構文全体で、P4 の意味 1 は「引数の境界」（`{}` の意味は 2 つのまま）。2 案を落とした:

- (a) **恒久不採用** LaTeX と同じ「1 文字で閉じる」 — 言語内で唯一「引数の終端が可視のデリミタでなく
  文字数で決まる」構文になり、`{}` / `[]` / `$` / `\end{}` で閉じる他のすべての引数と規則が割れる。
  さらに `+` `-` が構造文字でない現状の字句規則のもとでは `$x^-1$` が `x⁻1`（マイナス 1 乗ではない）に
  **診断なしで**化ける。「1 文字」を書記素クラスタで定義する
  字句概念の追加も要る
- (b) **恒久不採用** 裸のコマンド 1 個（`$x^\alpha$`）だけ許す — `$x^{\alpha}$` と字句挙動も出力も
  同一の第 2 の綴りになる（`$$` 不採用・`\pagebreak` エイリアス不採用と同じ理由。`\code` と `\mono` の
  ように別物として併存させる根拠＝字句挙動の差が無い）

#### 評価器にとって必須の情報を任意引数構文に置かない（2026-08、#453）— P2, P3

`\href` のリンク先は無ければ評価できない ＝ 評価器にとって必須なので、`[url=...]` の任意引数値ではなく
P2「必須引数は `{}` で明示し、個数・順序はコマンドごとに固定する」に従い `\href{リンク先}{表示テキスト}` の
2 必須引数にする（P3 は `[key=value]` という字面の規則で、必須のものを任意引数に置いてよいとは言っていない）。判定は「ハンドラがその値
なしで成功しうるか」— 成功しえないなら必須引数、既定値を持って成功しうるなら任意引数。どちらの引数を
第 1 にするかを裁く原則は無いので決めの問題として固定し、verbatim な側（リンク先）を先頭に置く（読み手が
「ここから生読み」を先に知れる）。第 2 引数を省略したときのフォールバック（表示テキスト＝リンク先）は
恒久的に足さない — それは `\href{U}` を `\url{U}` の第 2 の綴りにしてしまう（`\code` と `\mono` の判定と同型）。

#### 数式環境の本体先頭の `{...}` は数式グループ（2026-09、#732）— P2, P4, G1

`\begin{equation}{a}+b\end{equation}` の `{a}` を環境の引数として読むと、本体の 2 文字目以降の `{b}` は数式グループ
なので、同じグループが書いた位置で別の構文になる（G1）。`\begin{name}` の後ろの `{...}` を引数として読むのは、本体が `{` を内容として持てないテキスト本体の環境だけにする
— テキストでは裸の `{` は構文エラー（P4）なので引数以外の読みが立たず、`\begin{quote}{x}` は
「余分な引数」と環境名つきで診断できる。数式本体では `{...}` は P4 の「数式内グループ」なので本体になる。
必須引数を取る環境は無いので、環境の引数個数をレジストリから引いてパーサーが読む形（P2 の字面どおりの
個数固定）は見送る。再検討トリガーは必須引数を取る環境を初めて足すとき。コマンド呼び出しの `{...}` の
同じ問題（数式内の `\alpha{b}`）は下の #753 の事例。

#### 数式内のコマンドの個数を超えた `{...}` は数式グループ（2026-09、#753）— P2, P4, G1

`$\alpha{b}$` / `$\frac{a}{b}{c}$` の `{b}` / `{c}` をコマンドの引数として読むと、コマンドから離れた位置の `{...}` は
数式グループなので、#732 と同じく同じグループが書いた位置で別の構文になる（G1）。環境と違って数式内のコマンドには個数の決まった引数を取るもの（`\frac` は 2 個）が
あるので「数式内では引数として読まない」とは切れない。P2 は必須引数の個数をコマンドごとに固定しているので、
数式内ではパーサーがその個数を数式の語彙から引き、個数に達したら引数の読みを打ち切る — 後ろの `{...}` は P4 の
「数式内グループ」。個数の宣言は数式の語彙の 1 箇所に置き、パーサーの打ち切りと評価器の個数検査が同じ宣言に従う。
テキスト内のコマンドは裸の `{` を書けない（P4）ので引数以外の読みが立たず、`\bold{a}{b}` は
「余分な引数」と診断する。数式の語彙に無いコマンド（`$\code{...}$` 等）は評価器が未知のコマンドとして拒否する
だけなので個数で打ち切らない — 打ち切ると verbatim 宣言の引数（`$\code{a // b}$`）が数式として読まれ、
`//` がコメントとして後ろを食って「未知のコマンド」とは別の構文エラーになる。

#### 伸縮括弧は種類ごとのコマンドで、名前が種類を完結させる（2026-10、#644）— P2, P3, P7, G1

TeX の `\left( … \right)` は対になるトークンで区間を区切る構文で、引数の境界を `{}` で示さない（P2）。
中身の高さに合わせて伸びる括弧は `\paren{…}` `\bracket{…}` `\brace{…}` `\abs{…}` `\norm{…}`（#1012 で `\anglebracket{…}`
`\floor{…}` `\ceil{…}` を追加）の、必須引数 1 個・
オプションなしのコマンドにした。効果は引数に閉じ（P7）、種類はコマンド名が持つ（#84 のアクセントと同じ「名前が
指定を完結させる」。G1）。未知の種類は未知のコマンドとして拒否され、対にならない入力は構文上書けない（P6）。
縦棒・二重縦棒を `\abs` / `\norm` と呼ぶのは、`\bar` がアクセント、`\Vert` が記号として使用済みで、縦棒と二重縦棒を
形状名の対で揃えられないため。
直接書いた `(` `)` は伸びない 1 文字のまま残す — 中身が低いと同じ出力になるが、高い中身で結果が違うので第 2 の
書き方ではない。括弧で包んだ全体は左端を Open・右端を Close として隣とアキを取る（`\sum\paren{x}` は `\sum(x)` と
同じアキ）。大きさは cases / matrix・根号と同じ「覆う最小の字形」の規則（MathML Core の対称伸縮）で、TeX の
`\delimiterfactor` / `\delimitershortfall` 相当の係数は置かない。

- **恒久不採用** 1 つのコマンドに種類をオプションで渡す形（`\delimited[left=bracket, right=paren]{…}`）—
  評価に必須の種類を任意引数に置くことになる（#453 の判定で P2 の必須引数）。既定値を持たせると今度は種類を
  名前で完結させる #84 と衝突する。種類別コマンドとの併用は同じ結果への第 2 の書き方（G1）
- **恒久不採用** TeX の `\big(` `\Big(` `\bigg(` `\Bigg(` — `{}` で囲まない区切りを引数に取る（P2）
- **恒久不採用** TeX の Inner クラス — `f\left(x\right)` に細アキが入り、裸の括弧を伸縮括弧に替えるだけで横の
  アキが変わる（G3）
- **見送り** 個別の大きさの上書き（`\paren[size=…]{…}`。P10 上は「個の設定」としてソースのオプションに置ける）。
  再検討トリガーは入れ子の外側だけ大きくしたい等の具体要求。align の行をまたぐ括弧（`\Bigl( … \\ … \Bigr)`）は
  引数が `\\` をまたげないので、この上書きを足しても書けない（別の具体要求として扱う）
- **見送り** 非対称・片側だけの括弧（半開区間 `[a, b)`、評価棒）。再検討トリガーは具体要求。採るなら対称な組と
  両側なしを拒否する専用コマンドで、種類名を受け取る引数モードの設計が要る

#### 括弧のコマンド名は形状名を既定にし、用途名は形状名が使用済みで用途が 1 つのときだけ（2026-10、#1012）— P2, G1, G3

伸縮括弧のコマンド名は括弧の形状名を既定にする。用途名にするのは、形状名が使用済みで、かつ用途が 1 つに定まるとき
だけ — `\abs` / `\norm` は `\bar` / `\Vert` が使用済みで（縦棒と二重縦棒を形状名の対で揃えられない）、用途もほぼ 1 つなので用途名。山括弧・床・天井はこの規則で
`\anglebracket{…}` `\floor{…}` `\ceil{…}` とし、#644 の 5 種と同じ形（必須引数 1 個・オプションなし）・同じ組み方にした。

- `\anglebracket`: "angle bracket" は数学でこの字を呼ぶ標準の語で、Unicode の字名とも一致する。`\angle`（∠）と
  衝突せず、`\bracket` と並ぶ。字は `\langle` / `\rangle` と同じ U+27E8 / U+27E9（U+2329 / U+232A は NFC で CJK の
  U+3008 / U+3009 に写る）
- `\floor` / `\ceil`: 形状名と用途名が一致する。`\lfloor` ↔ `\floor` と `\lceil` ↔ `\ceil` が同じ対応になる
- `\langle x \rangle` / `\lfloor x \rfloor` / `\lceil x \rceil` と直接入力の ⟨ ⌊ ⌈ は伸びない 1 字のまま残す。中身が高いと
  出力が違い、閉じた箱かどうか（行分割点を持つか）でも違うので、第 2 の書き方には当たらない（#644 の直接入力 `(` と同じ）

- **恒久不採用** `\inner` — ⟨⟩ は内積のほか生成系・期待値・列・span にも使うので、用途名だと内容と食い違う（G3）
- **恒久不採用** `\chevron` — ‹› や矢羽形を指すことが多く、#87 の「最も分かりやすい語」に当たらない
- **恒久不採用** `\ceiling` — `\ceil` は数学・計算機の双方で通用する語で、`\ceiling` にすると `\lceil` との対応が崩れる

#### 中間の区切りは伸縮括弧の引数の直下だけで効くマーカー `\given`（2026-10、#1013）— P6, P7, G1, G3

伸縮括弧の中で外側の括弧と一緒に伸びる縦棒（TeX の `\middle|` 相当）は、引数もオプションも取らないマーカー `\given`
にした。置けるのは伸縮括弧の引数の直下だけで、字面上で最も内側の伸縮括弧に属し、1 つの括弧に何回でも置ける。効果範囲が
置き場所で一意に決まるのは、環境本体の直下だけで効く `\\` / `&` や行末の `\notag` と同じ型（P7）。伸縮括弧の外・グループ・
`\frac` などの引数・スクリプト・`\text`・行列や場合分けのセルに書くと `given_not_in_fence`、本文に書くと
`math_only_command` で拒否する（P6）。マーカーは括弧の種類と直交するので、内包表記（`\brace{x \given x > 0}`）も
条件付き確率（`P\paren{A \given B}`）も 1 つの語彙で書ける。

- 数式クラスは Rel で、`\mid` と同じアキを取る（中身が低い `\paren{A \given B}` は `(A \mid B)` と同じアキ）。Ord に
  すると、内包表記・条件付き確率のアキを著者が `\medspace` で足すことになり、見た目の判断がソースへ移る（G3）。
  マーカーは自分の大きさを持たず、縦棒は外側の括弧と同じ目標の高さ・同じ規則（数式軸を中心にした対称伸縮）で伸びる
- 縦棒の字は U+007C（`\abs` と同じ字）。数式フォント 8 種（STIX Two Math・Latin Modern Math・New Computer Modern Math・
  TeX Gyre Pagella / Termes Math・Fira Math・Libertinus Math・Garamond Math）で、U+007C はすべて縦の size variants と
  glyph assembly を持つが、U+2223 は Fira Math と Libertinus Math に縦の構成が無く伸びない。このため中身が低いときの
  字形は `\mid`（U+2223）ではなく直接入力の `|` と同じになる
- `\given` は新しい名前なので、`\mid` の読み方は一切変えない（`\paren{A \mid B}` の `\mid` は伸びない）。#644 が
  見送った「伸縮括弧の中の `\mid` だけを伸ばす案」（縦棒の書き方 3 つのうち 1 つだけが文脈で変わる）には当たらない
- 名前は、Rel のアキが合う用途（内包表記の such that、条件付き確率の given）と意味が揃い、mathtools の
  `\Set{x \given P}` の慣用とも一致する

- **恒久不採用** `\middle` — e-TeX の区切り引数付きプリミティブと同じ綴りで、偽の友になる（#87）
- **恒久不採用** `\middlevert` — 記号表では `vert` 語幹が Ord、`mid` 語幹が Rel なので、Rel のマーカーに付けると語幹と
  クラスが食い違う
- **恒久不採用** 伸縮括弧の中の `\mid` を伸びる縦棒として読み替える案 — 縦棒の書き方の 1 つだけが文脈で変わる（#644）
- **見送り** 集合の内包表記の専用コマンド `\set{要素}{条件}`。`\set` だけでは条件付き確率を書けず、用途ごとにコマンドが
  増え続ける。再検討トリガーは、内包表記の区切りを style.toml で `|` / `:` から選びたいという要求で、そのとき内容名
  として足す
- **見送り** 二重縦棒・スラッシュの区切り。再検討トリガーは具体要求。採るなら別名のマーカーにし、オプションで字を
  選ぶ形は恒久不採用（#644 の `\delimited[…]` と同じ理由）

#### 記号コマンドの名前は 1 字 1 名で、字を最も分かりやすく表す語にする（2026-10、#87）— P2, G1, P6

記号コマンドは引数を取らず、名前だけが出す字と数式クラスを決める。名前はその字を数学で呼ぶ最も分かりやすい語にする。
LaTeX（amssymb 等）の標準名があればそれを使い、unicode-math の名前は分かりやすいときだけ採る。暗号的な略記は語に
展開する（`vysmwhtsquare` → `tinysquare`、`tona` → `nwnearrows`）。大きさは tiny / small / mediumsmall / medium /
無印 / large、塗りは black を付け、白は付けない（無印の名前が使用済みか LaTeX の別コマンドと同じ綴りになるときだけ
`white` — `whitediamond`、`whitecircle`）。`math` 接頭辞は字体コマンド（`\mathbold` 等）と紛れるので付けない
（`\sterling` `\ratio`）。LaTeX の既存コマンドと同じ綴りは避ける（⧾ ⧿ は `\tiny` を避けて `\tplus` `\tminus`）。

LaTeX と同じ綴りの名前は、unicode-math がその LaTeX 名に対応づける字を指す（偽の友を作らない。G1）。このため
`\preceq` は ⪯（≼ は `\preccurlyeq`）、`\perp` は U+27C2、`\models` は ⊧（⊨ は `\vDash`）、`\blacktriangle` は ▴
（▲ は `\bigblacktriangleup`）、`\epsilon` は ϵ、`\phi` は ϕ。

同じ字・同じクラスに名前は 1 つ（`\land` を残し `\wedge` は持たない）。字が同じでもクラスが違えば出力のアキが違うので
別名ではない（`\triangle` Ord と `\bigtriangleup` Bin）。直接入力で同じ字・同じクラスになる ASCII には名前を置かず、
直接書けない `\`（`\\` は改行）と、直接入力とクラスが違う `:`（直接は Rel）だけ `\backslash` `\colon` を置く。
非 ASCII の字は直接書いても同じ字の記号コマンドと同じ記号になる（#959）。

数式用英数字（mathalpha）は字体コマンドが出し、記号名を置かない。字体コマンドで出せない字だけを記号コマンドにする
（`\Digamma` `\digamma` `\varTheta` `\turnediota` `\angstrom` `\hyphen` `\imath` `\jmath`。#948）。`\varTheta` は
unicode-math と同じ ϴ U+03F4（amsmath の斜体 Θ ではない）。`\angstrom` は Unicode の推奨形 Å U+00C5 で、U+212B は
NFC で U+00C5 になる正準等価な字なので、どちらを直接書いても `\angstrom` と同じ記号になる（#959）。`\imath` `\jmath`
はドット無しの字そのもので、アクセントの基底を `dtls` でドット無しにする #942 とは別の経路。Letterlike Symbols に
散在する黒板太字のギリシャ文字（ℼ ℽ ℾ ℿ）と太字の digamma（𝟊 𝟋）は、字体コマンドが英字の穴と同じく写す
（`\mathdoublestruck{\pi}` → ℼ、`\mathbold{\digamma}` → 𝟋）ので記号名を置かず、`\doublestruckpi` は持たない。
⅀ は字ではなく演算子なので `\doublestrucksum`（Op）を置く。字形ではなく意味を名指す記号（`\Re` 実部・`\Im` 虚部）は、
字体コマンドと同じ字（`\mathfraktur{R}` `\mathfraktur{I}`）になっても残す — 字体コマンドは見た目の指定、`\Re` は内容で、
別の書き方ではない（G3。§2 の判定）。

- **恒久不採用** LaTeX / unicode-math の別名（`\ne` `\varnothing` `\hslash` 等）— 同じ結果への第 2 の書き方（G1）。
  `\pagebreak` 事例の `\newpage` と同じ判定
- **恒久不採用** ASCII の記号名（`\lparen` `\equal` `\vert` 等）— 字を呼ぶだけの名前が直接入力と同じ結果になる
  第 2 の書き方（§2 の判定）。`\vert` は unicode-math の名前のまま残っていたのを #1014 で外した

#### 数式の演算子名は名前で limits を完結させる 32 個の組み込みで、字体コマンドに写されない（2026-10、#937）— P2, G1, G3, P6

LaTeX カーネルの演算子名 32 個を、数式専用・必須引数なし・オプションなし・Op の数式コマンドにした。名前は TeX のまま
（#645 と同じく、TeX の形のまま P2 に合う）。display 段で範囲を上下に積むかは名前が決める — 積むのは `\det` `\gcd` `\inf`
`\lim` `\liminf` `\limsup` `\max` `\min` `\Pr` `\sup` の 10 個（LaTeX で `\nolimits` の付かないもの）で、大型演算子と同じく
display 段でだけ真上・真下に積み、それ以外の段とほかの 22 個は肩・添字。largeop ではないので拡大しない。字は数式フォントの
立体の ASCII で、`\limsup` / `\liminf` の語の間は自動アキの細アキと同じ定数（#485 と同じく値ではなく定数を名指す）。

演算子名を立体で組むのは関数名の慣習（ISO 80000-2）で、内容の側にある。字体コマンドは数式用英数字（mathalpha）を写す
もので（写す先の無い字は `+` と同じく素通し）、演算子名は mathalpha ではなく関数名という語なので写す対象にならない —
`\mathbold{\sin x}` の `sin` は立体のまま、`x` だけが太字になる（#87 の `\mathbold{\digamma}` は字を写す場合）。文字色
（`\color`・リンク色）は継承する。裸の `\mathbold{\sin}` だけを拒否すると、`x` を変える `\mathbold{\sin x}` と一貫しないので
診断は置かない。

`\sin` と `\mathserif{sin}` は字形が同じでもクラスが Op と Ord で違い（`\sin x` には細アキが入る）、display 段の limits も
違うので別名ではない（#87 の「字が同じでもクラスが違えば別名ではない」。意味を名指す名前でもあり、§2 の判定でも第 2 の書き方ではない）。
`\limsup` と `\lim\sup` はスクリプトが無ければ同じ出力だが、`\limsup_{n}` は語全体の下、`\lim\sup_{n}` は `sup` の下に付いて
分かれ、互いの出力を含まないので第 2 の書き方ではない（#645 の基準。どの style・段でも恒等な `\qquad` とは違う）。

本文に書くと「数式の中でだけ使える」診断（#485）になる。記号コマンドの `\alpha` は本文でも字として使えるが、本文の `\sin`
は `sin` と打つことの第 2 の書き方になるので数式専用にする。数式に直接書いた `sin` は ASCII の字なのでイタリックの Ord 3 個の
まま（#959 が揃えるのは記号表の非 ASCII の字だけ）。

- **恒久不採用** TeX の後置 `\limits` / `\nolimits` — 引数を `{}` で囲まず（P2）、直前のアトムへ遡って効く（P7）
- **恒久不採用** `\operatorname*` の綴り — `*` は英数字ではない（P2）
- **恒久不採用** limits の有無を 1 つのコマンドのオプションで渡す形（`\operatorname[limits]{…}`）— 名前で種類を完結させる
  #644 / #645 と衝突する
- **見送り（恒久不採用ではない）** 利用者定義の演算子名。再検討トリガーは組み込みに無い名前（argmax / tr / rank 等）の
  具体要求か `\define` の実装。第一候補は #645 に倣って名前で分けた 2 コマンド `\operatorname{…}`（肩・添字）と
  `\operatornamewithlimits{…}`（display 段で上下）で、必須引数 1 個・中身は英字と `\thinspace` の許可リスト。組み込み
  32 個の綴りはどちらでも拒否して組み込みのコマンドを案内する（`\operatorname{lim}` は limits が違うので、同じ綴りで
  振る舞いが違う偽の友になる）。組み込みへ足すか利用者定義に回すかは、分野を越えて綴りが 1 つに定まるもの（ISO 80000-2 等）
  を組み込み、分野に固有のものを利用者定義とする案を起点にする
- **見送り** amsmath の `\injlim` `\projlim` `\varlimsup` 等と LaTeX に無い名前。`\varlimsup` は `\overline{\lim}` で書くと
  Ord になり limits も失うので表現力が実際に増えるが、下側の矢印（#645 で見送り）に依存する。再検討トリガーは具体要求
- **見送り** `\bmod` / `\pmod` / `\pod` — クラス（Bin）と括弧付きの特殊なアキで規則が違う。再検討トリガーは具体要求
- **見送り** limits の 1 個ずつの上書き。個の設定（P10）なので置くならソースのオプションで、大型演算子（`\sum` / `\int`）と
  まとめて扱う。種類（どの演算子か）ではなく配置の上書きなので、個別要素の設定とみなせるかの判断が残る。再検討トリガーは
  「インライン数式で `\lim` の下に置きたい」「表示数式の `\sum` を肩に置きたい」という具体要求
- **見送り** 太字の演算子名（`\boldsymbol` 相当）と、演算子名を本文書体で組む口（unicode-math の `\setoperatorfont` 相当。
  種類の既定なので置くなら style.toml）。再検討トリガーは具体要求
- **見送り** ㏒ U+33D2・㏑ U+33D1 等の互換字を演算子名として組むこと — NFC では写らないので #959 どおり Ord の字のまま
  （NFKC は使わない）。再検討トリガーは具体要求

#### 数式に直接書いた記号は、同じ字の記号コマンドと同じ記号として組む（2026-10、#959）— G1, P2, P6

数式に直接書いた字の結合文字列（基底の字と後ろに続く結合文字。#955）は、NFC にした最初の字が記号表の非 ASCII の字なら、
その記号コマンドと同じクラスの記号として組む（`$a≠b$` は `$a\neq b$` と同じアキ・行分割・大型演算子・区切りになる）。
字は書いたまま組み、クラスだけを記号表から取る。ASCII の直接入力は plain TeX の mathcode 相当のクラスのまま、記号表に
無い字（和文など）は Ord のまま。

記号コマンドは字を ASCII で書くための名前で、字そのもの（直接入力）と同じ記号を指す。#87 の「同じ字・同じクラスに
名前は 1 つ」は名前どうしの別名を禁じる規則で、字と名前はこの読み方で 1 対 1 に対応する。直接書ける ASCII に名前を
置かないのも同じ読み方の帰結である。

- 記号表で 1 つの字が 2 つのクラスを持つときは、unicode-math がその字に割り当てるクラスを取る。現在は U+25B3 △ だけで、
  直接入力は `\bigtriangleup` の Bin（Unicode の MathClass も B）。Ord で組むには `\triangle` と書く
- クラスは NFC にした字で引くので、正準等価な綴りは同じクラスになる（`=` + U+0338 は ≠ の Rel、U+0387 は U+00B7 の
  Bin）。記号表の否定形（≠ ≰ ∉ 等）は正準分解の基底と同じクラスを持つので、NFC で合成されない U+2ADC ⫝̸ も
  合成済みの字と同じクラスになる
- 結合文字が残る結合文字列（⊊ + U+FE00 の異体字、α̂）は基底の字のクラスを取る。display 段の大型演算子にはならない
  （大型演算子の伸縮は 1 字の字形に対して行う）

- **恒久不採用** 記号表の非 ASCII の字の直接入力を診断エラーにし、記号コマンドを案内する — Unicode を直接書けることは
  現代の組版システムの前提で、字面どおりの記号を拒否する理由にならない
- **恒久不採用** 直接入力した字を一律に Ord（ただの字）として組む — 字面が同じ記号のアキが書き方で黙って変わり（G1）、
  ASCII の `=` は Rel なのに `≠` は Ord という字面から読めない規則になる。unicode-math・Typst・MathML の演算子辞書も、
  直接書いた記号を記号として組む

#### 数式内の文章は `\text{...}` で、引数を本文と同じ読みで組む（2026-10、#977）— P2, P6, P7, G3, P10

数式の中に条件文や説明用の添字を書く口として、数式専用・必須引数 1 個・オプションなしの `\text{文章}` を置いた。引数は
外側が数式でもテキストとして読む（`_` `^` `&` は字、裸の `{...}` は P4 の構文エラー、エスケープは #967 と同じ）。語と語の
区切りは内容なので（G3）、連続するソース空白・単一改行は語間空白 1 個にまとめて残し、先頭・末尾の空白も残す。#86 の
「数式中のソース空白は組版に出さない」の例外ではなく、引数が数式ではなく文章であることの帰結である。記号コマンドは本文と
同じく直後の空白を食う（#516。`\text{\alpha b}` は「αb」）。

書体は style.toml の `[text].typeface`（本文の既定書体）で、インライン・表示数式・見出し・定理の中でも同じ。数式の中の文章の
書体は種類の既定なので（P10）置き場は style.toml で、本文の既定をそのまま継ぐ（#393 の単純継承）。和欧文間アキ・約物アキも
同じ表の `[text].punctuation_spacing` に従って入れる — 書体だけ借りてアキ調整を借りないのは借り方が一貫せず、アキを
ソース空白で代用させると見た目の判断がソースへ移る（G3）。大きさはその位置の数式段、色は外側の数式から継ぐ。数式クラスは
Ord の 1 アトムで、演算子名のアキも limits も付かない。字体コマンドは数式用英数字を写すもので文章は対象にならない
（`\mathbold{x\text{ if }y}` の `if` は本文の書体のまま。#937 と同じ判断）。引数全体を 1 個の閉じた箱にし、空白で
改行も伸縮もしない（アキは自然幅）。

`\text{sin}` と `\sin` はクラス（Ord / Op）も書体も違うので別名ではなく、#937 で見送った利用者定義の演算子名の代わりにも
ならない。空の `\text{}` は空のグループ `{}` と同じ空の Ord になるが、空でない引数では書体・空白・字体の扱いで必ず分かれ、
互いの出力を含まないので第 2 の書き方ではない（#645 の基準）。`\text{ }` は本文の語間空白 1 個ぶんの幅を持つ Ord で、
透過する明示アキ（#485）とは出力が違う。

受け付ける内容は字・空白・エスケープ・記号コマンドだけ（P6）。既知のコマンド（本文の装飾・参照・リンク・脚注、数式の
語彙）・`\\`・環境・入れ子の `$...$`・未知のコマンド・空行は拒否する。数式専用コマンドを「数式の中でだけ使える」診断
（#485）にしないのは、字面の上では `$` の中にいる利用者にそう案内すると食い違うため。`\text` の中の `\ref` / `\href` を許すと、#236 が見送った
「数式の一部だけをリンクにする形」が裏口から開くので拒否が必須。LaTeX の癖の `\text{a\,b}` は #967 の不要なエスケープ
として拒否される。

- **恒久不採用** `\mbox` / `\textrm` / `\textnormal` 等の LaTeX の別名 — 同じ結果への第 2 の書き方（G1。#87 の別名不採用、
  `\pagebreak` 事例の `\newpage` 不採用と同じ判定）
- **恒久不採用** `\textbf` / `\textit` 等、書体名を含む変種 — 「`\textbf` 系の削除と 12 装飾コマンド」の拡張規則と衝突する
- **恒久不採用** 本文での `\text` — `abc` と打つことの第 2 の書き方（#937 の本文の `\sin` と同じ）
- **見送り** `\text` の中の装飾コマンド（`\text{\bold{if}}`）。再検討トリガーは数式の中の太字・斜体の文章の具体要求で、
  #937 で見送った太字の演算子名と一緒に判断する
- **見送り** 外側（見出し・定理）の書体の継承。再検討トリガーは見出しの中の `\text` を見出しの書体に揃えたいという要求で、
  数式そのものを見出しの太さに合わせるかと一緒に決める
- **見送り** `[math].text_typeface`（指定しなければ `[text].typeface` を継ぐ `Option`）。再検討トリガーは数式の中の文章だけ
  本文と違う書体にしたいという要求
- **見送り** `\text` の中での `$...$` の再入（`\text{if $x>0$}`）。再検討トリガーは具体要求
- **見送り** 複数行・改行できる文章。再検討トリガーは具体要求（それまでは数式を閉じて本文に書く）
- **見送り** `\text` の中のリンク・参照 — #236 の見送りに従い、再検討トリガーも同じ

#### 数式の中で使える環境は matrix / cases だけで、数式の 1 要素として組む（2026-10、#978）— P5, P6, P7, G1

行列・場合分けは、それ自体が数式の内容になる。そこで `matrix` / `cases` 環境は、独立ブロックと同じ構文のまま数式の途中
（インライン数式・表示数式のセル・数式引数・matrix / cases のセル）へ書ける。埋め込んだ全体は閉じた
1 個の数式要素で、行分割・改ページをせず、採番もしない。番号・ラベルは外側の equation / align 等の行に付く。
内側への `numbered` / `label` オプション、`\label` / `\notag` は、独立ブロックと同じく未知のキー・非対応の行末マーカーとして
拒否する。数式の中で使える環境の許可リストは evaluator の 1 箇所にある（P6）。新しい環境を足すときは、そこで数式の中で
使えるかを判断する。行・列区切り `\\` / `&` は、それぞれの環境本体の直下にだけ効く。内側の区切りは環境本体の
構文木の中に閉じるので、外側の align や matrix の行・列を割らない（P7）。表示数式の境界は表示数式全体の環境
（equation / align / gather / split / multiline）だけが作り、行列を埋め込んでもインライン数式はインライン数式のまま（P5）。

- **恒久不採用** 表示数式全体の環境（equation / align / gather / split / multiline）を数式の中へ入れ子にすること —
  表示数式の境界が字面から一意に決まらなくなる（P5）
- **恒久不採用** 埋め込み専用の別名の環境・コマンド（`pmatrix` / `\matrix{…}` 等）— 同じ結果への第 2 の書き方（G1）

#### 二項係数は `\binom{上段}{下段}` の固定 2 引数で、括弧と段は周囲から決める（2026-10、#979）— P2, P7, G1, G3, P10

二項係数は、内容を名前で指定する数式専用コマンド `\binom{上段}{下段}` にした。必須引数は 2 個・順序固定・オプションなしで（P2）、
効果は引数に閉じる（P7）。上段・下段は分数の分子・分母と同じ段と cramped で組み、横罫を引かずに積む。全体を伸縮丸括弧で包んだ
閉じた 1 要素にする。積みのシフトとギャップはフォント実体の OpenType MATH の `Stack*` 定数から決める（MathML Core §3.3.2.2）。
括弧の大きさは伸縮括弧（#644）と同じ「覆う最小の字形」で、TeX の `\delim1` / `\delim2` 相当の定数は置かない。いずれも
ソースのオプションにも style.toml にも置かない（P10・#91）。`[math.block].row_gap` は効かない（`\binom` は行列ではなく分数の仲間）。
隣とのアキは左端 Open・右端 Close で取る。これは #644 で TeX の Inner クラスを恒久不採用にした帰結で、amsmath の `\binom`
（`\genfrac` の Inner アトム）とは違い、`\paren{…}` と同じアキになる。最も近い既存の書き方は、数式に埋め込んだ 1 列の行列
（`\begin{matrix}[delimiter=paren]n \\ k\end{matrix}`、#978）だが、第 2 の書き方ではない。インライン数式で行列のセルは text 段の
まま、`\binom` の上下は script 段に下がり下段は cramped になる。この差は style.toml によらず必ず出る（#645 / #904 の基準）。
上下のアキも、`Stack*` 定数と `row_gap` で出どころが違う。`\paren{\frac{n}{k}}` とは分数線の有無で、どの入力でも出力が違う。

- **恒久不採用** 中置の `\choose` と、TeX の他の中置の分数の仲間（`\over` / `\atop` / `\above`）— 引数境界を `{}` で示さず（P2）、
  外側のグループの中で自分の前後へ遡って効く（P7。#937 の `\limits` と同じ形）
- **恒久不採用** 積みと括弧の種類をオプションで選ぶ汎用コマンド（`\genfrac` 相当）— #644 の `\delimited[left=…, right=…]` と同じ
  筋で、評価に必須の種類を任意引数に置くことになり（#453 の判定で P2 の必須引数）、既定値を持たせると名前が種類を完結させる規則
  （#84 / #644）と衝突し、`\frac` / `\binom` との併存は第 2 の書き方になる（G1）
- **見送り** 段を強制する `\dbinom` / `\tbinom`。段の上書きは新しい種類ではなく、同じ種類のまま個の設定を変えるもの（#942 の
  `dotless`、#937 で見送った limits の 1 個ずつの上書きと同じ型）。再検討トリガーは段の上書きの具体要求で、第一候補は `\frac` と
  `\binom` で共有するソースのオプション。そのとき専用の名前はオプションの第 2 の書き方になる（G1）
- **見送り** 1 個ずつの線の太さ・ギャップの上書き（P10 上は個の設定としてソースのオプションに置ける）。再検討トリガーは #84 / #645 と
  同じく「特定の 1 個だけ直したい」という具体要求
- **見送り** 括弧の付かない線なしの積み（`\atop` の結果に当たるもの）や、名前付きの別の積み記法（スターリング数等）。採るなら #644 の
  「種類ごとに名前のあるコマンドを足す」道で、再検討トリガーは具体要求

### P3 オプション引数は名前付きのみ

#### 任意引数は 1 組・キー重複はエラー（2026-08、#488）— P3, P6, G1

`[a=1][b=2]` のような複数組は `[a=1, b=2]` と同じ結果への 2 通り目の書き方（G1）なので構文エラーに、重複は先勝ち・後勝ちのどちらにも倒さず
エラーにする（P6: 黙って片方を採るのは静かな無視）。通常のコマンド・環境はトリビアを跨いで引数を探すので、
空白・改行を挟んだ `[` も 2 組目として同じエラーになる（`[` は本文に書けない文字なので別の読みが立たない）。
verbatim 環境は例外ではなく規則の帰結 — `\begin{<環境名>}` に隣接する 1 組だけを任意引数として読み、
それ以外は本体のバイトになる（#447 の生読み境界）ので、2 組目相当の `[...]` は「`[` で始まる本体」であって
構文エラーにはしない。

#### 任意引数値の `,` `=` はエスケープで書き、引用符は境界にしない（2026-09、#687）— P3, P1, G1

区切りは構造トークンとしての `,` `=` だけで判定し、`\,` `\=` は値の文字にする — 構造文字が構造として働くのは
固定の文法が意味を与える位置だけで、それ以外では自分自身の文字に戻る（本文の `&` `_` `^` と同じ規則）。
引用符を値の境界にする案は恒久不採用: lexer 上ただの文字である `"` の役割が位置ではなく値の形で決まり
（P1「文脈によって役割が変わる文字を作らない」）、`"a, b"` と `a\, b` の 2 通りの書き方も生む（G1。`$$` / `\[`
不採用と同型）。題名中の引用符と境界の取り合いにもなる（#453 で任意引数値の verbatim 化を退けたのと同じ理由）。
`{a, b}` で囲む案は `{}` に第 3 の意味を作るので P4 に衝突する。値全体が `"…"` の旧ソースを専用の診断で拒否する
移行ガードも入れない — どの原則からも導けず、旧形式は未知キーや値の不正として自然にエラーになるか、
引用符が PDF 上に見える（静かな無視ではない）。未知キーの診断が `\,` / `\=` を案内する。
`\cite` のキーの区切りも同じ規則に従う — 区切りは構造トークンとしての `,` だけで、`\cite{a\,b}` は 1 つのキー
`a,b` になる（`references.toml` に無ければ未知キーとして拒否。#731）。未定義キーに `,` が含まれるときは、
その診断が `\,` はキーの文字で区切りはエスケープしない `,` だと案内する（#751）。

#### 長さの書式は言語全体で 1 つ（2026-09、#690）— P3, G1, P6

長さの字面は
ソースの任意引数・必須引数（`\space`）・table の `widths`・style.toml・config.toml で同一とし、数値と単位を空白なしで
続け、単位は小文字の `pt` / `mm` / `cm` のみで必須とする（`pt` は 1/72 in）。単位のない数値を暗黙の単位で読むのは
推測で処理を続けることそのもので（P6）、`50` / `50mm`、`5MM` / `5mm`、`5 pt` / `5pt` は同じ結果への 2 通りの
書き方になる（G1。`$$` / `\[` 不採用と同型）。書式と値域は分ける — 書式は 1 つ、値域（`\image` の `width` /
`height` と `widths` の固定幅は正、`item_gap` と `\space` は符号付き）はキーごとのスキーマが上に重ねる。
単位なしの `0` も例外にしない: 例外にすると `0` / `0pt` の 2 通りの綴りと「単位必須、ただし 0 は除く」という
場合分けが生まれ、`widths` の比率の読みともぶつかる。単位のない数値は `widths` の比率としてだけ残る — 型が
字面の単位の有無だけで決まるので規則は 1 つで、本文幅に対する割合は絶対長で書けないので長さの第 2 の綴りでも
ない（表現力が増える側。#457 と同じ論法）。比率に `%` のような目印を付ける案は採らない（P1 で予約済み）。
他の単位は見送り（恒久不採用ではない）: 絶対単位（`in` / `bp`）は「US 用紙を in で書きたい」のような具体的な
要求が再検討のきっかけ、相対単位（`em` / `ex`）はフォント文脈に依存する別機能として扱う。旧書式専用の移行
ガード診断は入れない（#687 と同型。旧形式は値の不正として自然にエラーになる）。任意引数の真偽値も同じ論法で
小文字の `true` / `false`（と bare key）だけを受理する — `True` / `TRUE` は同じ値への第 2 の綴りで（G1）、黙って
小文字へ正規化するのは P6 に反する（#739）。`matrix` の `[delimiter=...]` のような列挙値も同じで、小文字の綴りだけを
受理する（#945）。色の `#rrggbb` の 16 進は大文字小文字不問 — `#FF0000` / `#ff0000` も同じ論法の対象になりうるが、
見送り（恒久不採用ではない）で、色の書式に手を入れる機会が再検討のきっかけ。

### P4 `{}` の意味は 2 つだけ

#### verbatim 引数のブレースバランス走査は P4 の「引数境界」（2026-08、#447）— P4, P2, P6

verbatim 宣言されたコマンドの必須引数は、対応の取れた `{}` を本体に含め対応しない `}` で終端する走査で
読む。これは `{}` の意味 1「コマンドの引数の境界」の解釈であって第 3 の意味を作らない（P4 は 2 つのままで、
例外を継ぎ足していない）。終端規則は全 verbatim 引数で統一しコマンドごとに変えない（G1: 字面だけで
どこまでが引数か一意に読める）。バランスしないブレースを含む内容は verbatim 環境（ブロック）へ逃がす —
言語内に閉じた逃げ道があるので、`\verb|...|` 式の可変デリミタ（P2 違反）は要らない。ブロック側の終端は
`\end{<環境名>}` の正確なバイト列一致 1 個だけで、`\end {code}` のような変形は一致せず、本体内の
`\begin{<環境名>}` も計数しない。未終端はどちらもエラー（P6。「閉じない `$` はエラー」と同型）。

### P7 効果範囲の構文的閉包

#### `\notag` — P7

align / gather の行末マーカー。効果はその行のみ・置ける位置も行末で一意（P7 (c) 適合）。

#### `\textbf` 系の削除と 12 装飾コマンド — P7, P10

`\serif` / `\bold` / `\italic` / `\bolditalic` / `\sans` / `\sansbold` / `\sansitalic` / `\sansbolditalic` /
`\mono` / `\monobold` / `\monoitalic` / `\monobolditalic`（3 ファミリ × 4 スタイル、内側が完全上書き）。
引数型で閉じ（P7）、ソースは「太字という種類」だけを書き実体フォントは config.toml が決める（P10）。
**拡張規則**: 新しい装飾は合成可能なモディファイアではなく「完全な書体を 1 コマンドで指定する」形で
追加する（`\textbf` / `\emph` のようなモディファイアは親スタイルとの合成が破綻する）。`\color`（#31）は
書体と直交する属性なので装飾の完全上書きとは別系統で、上書きではなく合成される（`\bold{\color[...]{x}}` も
逆順も両方効く）。コマンド名は `\textcolor` ではなく `\color`（`\bold` / `\sans` と同じ text 接頭辞なし規則）。

#### `\pagebreak`（2026-07）— P7, P10, P6

その位置で強制改ページするマーカー。引数なし・任意引数なしで、効果が 1 点に閉じ置ける位置も一意なので
P7 (c) 適合（`\notag` と同型）。エイリアス（`\newpage` / `\clearpage`）と強度オプション（`[weight=0-4]`）は
不採用 — 同じ結果への書き方を増やさない（`$$` 不採用と同じ理由）。style.toml `[heading.<level>].page_break_before` /
`page_break_after` が「見出しという種類の既定」、`\pagebreak` が「この 1 点」の個別指定で P10 適合。段落の
途中・quote / theorem / list 項目の本体に書けるのは許容（P6 は未知のコマンド・キーを拒否する原則であって
位置の妥当性を裁く原則ではない。同じ挙動の先例が `\space{<長さ>}`）。内容（本文または確定脚注）を挟まない位置
（文書先頭・連続・末尾）では冪等な no-op として畳む — 「実際にページを送るか」は組版結果に依存し
フロントエンドでは判定できず、break 段でエラーにすると span を失って診断が劣化するため。インライン文脈
（脚注・表セル・キャプション）はエラーで拒否する（P6）。

#### `\index` を置ける位置は「配置が一意か」で決める（2026-09、#246 → #510）— P7, P6

`\index{語}` は幅 0 のマーカーで、意味は「この内容がどのページに落ちたか」だけである。したがって置ける位置の
妥当性は、`\pagebreak` のような inline / block の区別ではなく **その内容の配置が一意に決まるか** で判定する
（`\pagebreak` が組版効果を持つためブロック境界を要求するのとは基準が違う。両者とも「その文脈で意味を持つか」
という同じ問いに、効果の性質が違うので違う答えが出る）。

- **許可**: 本文段落・箇条書き・定理環境に加え、書体 / 色指定コマンドの引数内・脚注本体・図表キャプション・
  表の `\row` / `\cell` 本体セル。いずれも内容が 1 箇所にしか置かれないので、出現ページが一意に定まる。
  脚注が行単位でページ繰越した場合も、表が改ページした場合も、帰属先は**マーカーを含む行が実際に落ちたページ**。
- **拒否**: 表の `\head` セル（表が改ページするたび全ページへ再描画される複製文脈で、出現ページが一意に
  定まらない）・見出しタイトル（目次・走り文へも展開されうる）・`\href` の表示テキスト・`\index` 自身の語。
  拒否は静かな無視ではなくソース位置付きエラー（P6）。

書体 / 色指定と脚注本体は**外側の文脈の可否をそのまま引き継ぐ**。固定で許可にすると
`\section{\bold{x\index{x}}}` や `\head{\row{\bold{x\index{x}}}}` が拒否をすり抜けるため。
`\head` の許可は見送りで、再検討トリガーは
「複製文脈での出現ページ帰属規則を定義できる具体案」。

#### リンクは本文側の `\href` が数式を包み、数式の語彙には入れない（2026-10、#236）— P7, P5, P6, G1

数式をリンクにするには、`\href` の活性な第 2 引数にインライン数式を置く（`\href{uri}{$x^{2}+y^{2}$}`）。
新しい構文は足さず、効果は `\href` の引数で閉じる（P7 (a)）。数式は引数の中の内容の 1 つで、数式境界は
`$...$` のまま（P5）。行をまたぐインライン数式は本文テキストのリンクと同じく行ごとに矩形が分かれる — 範囲は
引数のままで、分かれるのは描画だけ。`\ref` と `\url` には表示を取る引数が無い（表示は採番結果と URI そのもの）
ので数式を包めるのは `\href` だけになるが、欠けているのは内部参照の表示を著者が決める口で、数式に固有ではない。
数式内の `\ref` / `\url` / `\href` は数式の語彙に入れず、未知のコマンドとして拒否する（P6）。
数式の一部だけをリンクにする形（`$\ref{eq:1}+x$`）は**見送り（恒久不採用ではない）**。厳密に表現力が増える側で
第 2 の書き方には当たらない（#457 (b) と同じ判定）が、採るには数式内のリンク範囲（P7）、参照の表示を数式クラス
（#86）のどれとして組むか、数式全体を包む `$\href{u}{x}$` が `\href{u}{$x$}` の第 2 の綴りになる問題（G1）を
解く必要がある。再検討トリガーは「式の中の 1 項だけを参照先へ飛ばしたい」という具体要求。

### P8 マクロ置換なし

#### 定理環境は 10 種固定 + style.toml 宣言（2026-06、#52-54）— P8, G1

amsthm の `\newtheorem` はマクロ定義そのもので P8 と矛盾するため、定理クラスは style.toml で宣言しソースは
環境名で参照する。環境名は amsthm 標準 10 種（theorem / lemma / proposition / corollary / definition / axiom /
example / remark / claim / proof）で固定し、平易化リネーム（remark→note 等）は不採用。proof のみ無採番で
QED マークを自動配置。証明は独立環境で直前の定理との暗黙紐付けはせず、明示リンクは `[of=...]` のみ
（G1: 関係が字面から一意）。カウンタ共有は `counter` フィールドへの同名指定（LaTeX
`\newtheorem{lemma}[theorem]` の第 2 引数の明示化）、リセットは見出しカウンタの増加時のみ（上位リセットでは
戻さない。LaTeX 準拠）。番号書式は "1" / "i" 等の番号スタイルではなくテンプレート文字列
（`number_format = "{n}"` / `"{chapter}.{n}"`、counter の `number_format` と同形）。`\ref` の表示は
`"{display_name} {number}"` 固定で、定理クラスは ref_format フィールドを持たない。ユーザ独自クラスは
見送り。

#### `\define` のスコープ — P8, P10

対象はコマンドのみで、ユーザ定義環境はサポートしない（環境は前後処理が必要で固定引数のコマンド定義では
表現できず、P8 の範囲を環境へ広げない。必要が出たら将来検討）。定義の置き場所は専用の `.seiran` ファイル
（§1。ソース構文を流用して frontend の syntax を再利用する。TOML 内蔵は `\\` の二重エスケープが要るため
不採用）で、config.toml の `commands_path` で指定する（P10: どの定義を読むかは実体）。

### P10 内容と見た目の分離（G3）

#### `\input` 不採用 — P10

ソースの合成は config.toml の `sources` で行う。どのファイルをどの順で束ねるかは「実体」であり config の管轄。

#### キャプション位置はソース出現順で決定 — P10

`\caption` が本体より前なら Top、後なら Bottom。ソースの順序＝内容の順序。

#### 数式番号の 3 系統（tag / number / ref）— P10

式の横に出す tag は `[math.block].tag_format`、採番書式・参照書式は `[counters.equation]`。いずれも種類既定
なので style.toml。

#### 表示文字列の i18n は style.toml の明示指定のみ — P10

既定は英語（"Theorem" / "Figure" / "Table" 等）で、`[counters.*].display_name` 等の上書きで日本語化する。
内蔵 locale（`ja` / `en`）の切替スイッチは設けない — 表示文字列は「種類の既定」で style.toml の管轄そのもの
であり（P10）、切替スイッチは同じ結果への第 2 の書き方になる。ハイフネーション・禁則の言語はフォントという
実体に付く属性なので config.toml（P10）。

#### 数式レイアウト定数はフォント実体（OpenType MATH テーブル）由来 — P10, P6（2026-09、#91）

上付き下付きのシフト量・縮小率等は「見た目の種類既定」ではなくフォントの実体に属する値（P10）なので、style.toml に
置かない（非対応フォント用のフォールバック設定としても置かない）。数式フォントには MATH テーブルを必須とし、持たないフォントは
診断エラーにする。内部の固定値による近似へ黙って落とすのは P6 に反し、近似を残すと検証されない第 2 の組版経路と
隠れた定数が残る。

#### 数式フォントに無い字は使用時に診断エラー — P6（2026-10、#941）

数式で使った字（数式用英数字は写した後の字、記号・アクセント・根号・区切り括弧を含む）の基本の字形が数式フォントの cmap に
無ければ、.notdef で組まずソース位置付きの診断エラーにする（warning にしない・別フォントで代替しない）。黙って豆腐を出すのは
静かな無視（P6）。検査はフォント読込時ではなく使用時 — 必要な字の集合は文書ごとに決まり、文書が使わない珍しい記号が無い
だけのフォントを拒否しないため（MATH テーブル必須は全文書の前提なので読込時に検査する #91 とは性質が違う）。派生字形
（`ssty`・`flac`・size variant・glyph assembly）は基本の字形から派生するか既定に戻るだけなので検査しない。和文として明朝体へ
振り分ける字は数式フォントの対象外。

#### 数式アクセントは名前で種類を完結させ、位置と高さにノブを置かない（2026-10、#84）— P10, P2, G1

`\hat` `\bar` `\vec` `\dot` `\ddot` `\tilde` `\check` `\acute` `\grave` `\breve` は必須引数 1 個（基底）の数式専用
コマンドにした（オプションは基底の字形を選ぶ `dotless` だけで、位置・高さのノブではない。#942）。種類はコマンド名が持ち、`\accent[type=hat]{x}` のように引数で選ばない（12 装飾コマンドと同型の
「名前が指定を完結させる」。G1）。アクセントの位置・高さは数式フォントの OpenType MATH（`MathTopAccentAttachment` /
`AccentBaseHeight` / `FlattenedAccentBaseHeight` と `flac`）が決めるフォント実体の値なので、#91 と同じく style.toml には
置かない（P10）。ソースで 1 個ずつ位置を調整するオプションは P10 上は「個の設定」として許されるが、具体要求が無いので
**見送り（恒久不採用ではない）**。再検討トリガーは「特定の 1 個だけアクセント位置を直したい」という具体要求。

#### アクセントの基底のドット無しの字形は style.toml の既定とアクセント 1 個のオプションの 2 層（2026-10、#942）— P10, P3, P6, G1

アクセント（`\hat` 等の 10 コマンド）の基底が数式フォントの 1 グリフなら、そのグリフに OpenType `dtls` を当てたドット無しの
字形で組む（`$\hat{i}$` のアクセントが i のドットの上に載らず、ほかの小文字と同じ高さになる）。字は替えず字形だけを替える
ので内容は変わらない（G3）。数式組版の慣習で、`dtls` はアクセントを載せる基底のためのフィーチャなので、#84 の「位置・高さは
フォントの設計意図に従う」とも合う。置換の有無はフォントが決め、i・j を名指す規則はコードに持たない（数式用英数字の
ドット無しの字は Unicode に数式用イタリックの 2 字しか無く、字を置き換えるのでは字体を網羅できない）。

ドット無しが常に望ましいとは限らない（`\dot{i}` の時間微分はドット無しの ı にドットが載り素の i と見分けにくい）ので、
切り替えを 2 層にした。文書全体の流儀は style.toml の `[math].accent_dotless`（真偽値、既定 `true`。見た目の種類の既定で
P10。フォントが持つのは `dtls` を使える能力で、使うかは見た目の選択。単一スカラーなので副テーブルを作らない。#393）。
アクセント 1 個の上書きはソースの任意引数 `dotless`（真偽値。裸のキーは `dotless=true`。P3）で、`\dot{i}` を 1 個だけ
ドット付きにする具体要求が P10 の「まず種類既定で足りないか」を越える。型は画像 DPI（config.toml `[image].max_dpi` +
`\image[dpi=...]`）と同じ。#84 が見送ったのは位置・高さのノブで、字形の選択はそれとは別の軸なので、#84 の「名前で種類を
完結させる」とは衝突しない（種類はコマンド名が持ち、`dotless` は同じ種類のアクセントの基底の字形を選ぶだけ）。
`\hat[dotless=false]{i}` は既定の下でドットを残す唯一の書き方で、第 2 の書き方ではない（G1）。

`dotless` は「このアクセント 1 個について style.toml の既定を上書きするキー」で、既定が効かない基底（複数グリフ・
スクリプト付き・分数等、`dtls` に置換の無いグリフ）では上書きも効かない。そこに書いた `dotless` は受理して出力を変えない
（P6 が拒否するのは未知のキーで、既知のキーの使い方の妥当性ではない。`dtls` の置換の有無はフォント実体次第で組版まで
分からず、拒否すると config.toml のフォントを替えただけでソースがエラーになる）。広幅アクセント（`\widehat` 等）は
`dotless` を持たず未知のキーとして拒否し、style.toml の既定も効かない — 広幅の基底は 1 グリフとは限らない。

ドット無しの i・j を書く `\imath` `\jmath`（#948）はドット無しの字そのもの（ı と i は字が違う）で、基底の字形を `dtls` で
選ぶこの経路とは別。

- **見送り（恒久不採用ではない）** 広幅アクセントの基底のドット無し（`\widehat{i}`）。再検討トリガーは具体要求で、#645 の
  事例と合わせて決める

#### 広幅アクセントと上下線は名前で種類を完結させ、`\hat` 等とは統合しない（2026-10、#645）— P10, P2, G1, P6

`\widehat` `\widetilde` `\widecheck` `\overrightarrow` `\overleftarrow` `\overleftrightarrow`（記号を引数の送り幅へ横にだけ
伸ばす）と `\overline` `\underline`（引数の送り幅いっぱいの罫線）は、必須引数 1 個・オプションなし・Ord の数式専用
コマンドにした。種類はコマンド名が持ち（#84 / #644 と同じ。G1）、名前は TeX / LaTeX を踏襲する（TeX の形のまま P2 に
適合するので変える理由がない）。記号の大きさは #644 の括弧・根号と同じ「覆う最小の字形」の横版（MathML Core の shape a
stretchy glyph）で、横の伸縮を持たない
記号が元の字形のまま、覆いきれない記号が最大の size variant に落ちるのはフォントの能力から決まる結果であり、隠れた定数による
近似（#91 が退けた形）ではないので P6 の静かなフォールバックに当たらない。位置・高さ・罫線の太さとギャップは数式フォントの
OpenType MATH（`MathTopAccentAttachment` / `AccentBaseHeight` / `Overbar*` / `Underbar*`）が決めるフォント実体の値なので
style.toml に置かない（P10。#84 と同じ）。全体の幅は引数の送り幅で、`\hat` → `\widehat`、`\bar` → `\overline` と置き換えても
横のアキは変わらない（G3）。

`\hat` / `\widehat`（`\tilde` / `\check` も）と `\vec` / `\overrightarrow` は狭い引数で同じ出力になりうるが、広い引数で
分かれ、互いの出力を含まない（広い引数の上の固定幅の記号は `\widehat` で出せない）ので第 2 の書き方ではない（#644 /
#904 の基準）。`\bar` / `\overline` はグリフと罫線でどの引数でも出力が違う。

- **恒久不採用** `\hat` 等を引数幅へ伸ばし、`\widehat` 系を足さない統合案 — 「広い引数の上の固定幅アクセント」が書けなく
  なる。`\vec` / `\overrightarrow`、`\bar` / `\overline` は別の慣用を担うので統合できず、hat / tilde / check だけ統合すると
  「短い名前は固定幅、`wide*` / `over*` は引数幅に追従」という名前の規則が割れる
- **恒久不採用** 伸縮の有無・種類をオプションで渡す形（`\hat[wide]{…}`・`\accent[type=…]{…}`）— 評価に必須の種類を任意
  引数に置くことになり、#84 / #644 の「名前で完結」と衝突する。種類別コマンドと併用すると第 2 の書き方になる
- **見送り（恒久不採用ではない）** 下側の矢印（`\underrightarrow` `\underleftarrow` `\underleftrightarrow`）— OpenType
  MATH には下付けの縦位置の定数（`AccentBaseHeight` の下側版）も `MathBottomAccentAttachment` も無く、フォントの設計に
  乗れない（自前の規則か定数が要る）。再検討トリガーは具体要求。採るときは MathML Core の accentunder の規則を借りられる
  かを先に確かめる
- **見送り** 1 個ずつの位置・太さの上書き。再検討トリガーは #84 と同じ（特定の 1 個だけ直したいという具体要求）
- **スコープ外の予告** 注釈付きの上下括弧（`\overbrace{…}^{…}`）を採るなら、`^` が「上付き」と「括弧の注釈」で意味が
  割れる（G1 / P2）ので、注釈を第 2 必須引数にする形（`\overbrace{基底}{注釈}`）を第一候補にする

#### 数式の明示アキは種類を名指す 5 コマンドで、自動アキに透過する（2026-10、#485）— P10, P2, G1, P6

#86 で数式のソース空白を組版に出さなくしたので、著者が明示的にアキを入れる手段として、数式専用・引数なし・オプションなしの
`\thinspace`（3mu）`\medspace`（4mu）`\thickspace`（5mu）`\quad`（18mu = 1em）`\negthinspace`（−3mu）を置いた。名前は
LaTeX / amsmath を踏襲する（記号名 `\,` `\:` `\;` `\!` は P2 で使えず、英数字名はそのまま P2 に合う。#645 と同じ。記号名を書くと不要なエスケープとして拒否される（#967））。
コマンドは量ではなく種類を名指す — 細・中・太は自動アキと同じ定数を指し（`\thinspace` は自動アキの細アキそのもの）、
#86 の再検討トリガーで量を `[math.spacing]` へ移すときも明示コマンドが同じ値に従う（P10。量を名指す `\mspace{3pt}` 型より
G3 に強い）。量はすべてその段のフォントサイズの mu で、`\quad` もスクリプトの中では縮む（LaTeX の `\quad` は本文の em の
まま）。スクリプトの中でも消えない（自動アキの text 段だけのセルとは別）。

明示アキはクラスを持たず、アトムに数えない — Bin→Ord 変換とクラス間の自動アキは明示アキを飛ばして隣のアトムどうしで
決め、明示アキの幅はその位置の自動アキに足す（`$a\thinspace+b$` の `a` と `+` の間は中アキ + 細アキ、`$-\thinspace x$`
の `-` は単項のまま）。スクリプトの基底にもならない（`$x\thinspace^{2}$` の `2` は空の基底に付く）。明示アキの位置は
行分割点にせず（分割点はトップレベルの Bin / Rel の直後だけ）、演算子直後の分割点で折り返すと、その境界の明示アキは
自動アキとともに行頭から消える。`{\thinspace}` はグループなので Ord 1 個で透過しない（結果が違うので第 2 の書き方では
ない）。

数式専用コマンド（明示アキに限らず `\frac` `\sqrt`・伸縮括弧・アクセント・上下線・字形コマンド）を本文に書くと、未知の
コマンドではなく「数式の中でだけ使える」診断になる — 評価器はこれらの名前を数式の
語彙として持っているので、書き直し先（数式の中）を示せる。記号コマンド（`\alpha` 等）は本文でも字として使えるので対象外。
逆向き（本文のコマンドを数式に書く）は #236 どおり未知のコマンド（P6）のまま — 本文のコマンドには数式の中での対応物が
一般に無く（`\ref` / `\url` を数式の語彙に入れない判断、#236）、「本文でだけ使える」と言っても書き直し先を示せない。

- **恒久不採用** `\qquad`（36mu）— どの style・段でも `\quad\quad` と恒等で、同じ結果への第 2 の書き方（G1。`\newpage`
  不採用と同型）。別の定数を指す名前の合成（`\thinspace` 6 個と `\quad`）は、量を style へ移せば分かれるので冗長ではない
- **見送り（恒久不採用ではない）** `\negmedspace` / `\negthickspace`。再検討トリガーは具体要求
- **見送り** 量を指定するコマンド（`\mspace` 類）。再検討トリガーは「固定 5 種で足りない量」の具体要求と、単位の問題
  （mu は言語の長さ単位に無く、相対単位は #690 で別機能として見送り済み）の解決の両方。採るなら量は評価に必須なので
  必須引数（#453）
- **見送り** 数式に直接書いた Unicode の空白（U+205F MEDIUM MATHEMATICAL SPACE 等）をアキとして組むこと — 今はほかの
  空白と同じく組版に出さない（#86 の 1 規則）。対応する字をコマンドへ写すと空白文字が内容を持つことになる。再検討トリガーは
  「U+205F を中アキとして書きたい」等の具体要求
- **見送り** 本文で使える em 基準の水平アキ（`\quad` の本文版）。本文の固定幅のアキは `\space{<長さ>}`。再検討トリガーは
  具体要求

#### ページ余白を config.toml から style.toml へ（2026-08、#389）— P10

余白は「用紙という実体の物理量」ではなく「用紙をどう使うか」なので P10 の判定では種類の既定＝見た目。
`[page]` に `margin_top` / `margin_bottom` / `margin_left` / `margin_right` をフラットに置き（`[page.margin]` の
副テーブルは作らない）、用紙寸法は `config.toml` の `[pdf]` に残す。これで不変条件「同じ本文 + 同じ用紙で
style.toml だけ差し替えて見た目を変えられる」が版面の広さにも成り立つ。

#### 表ヘッダ行の書体を style.toml へ（2026-08、#393）— P10

`\head{}` セルの書体は「表という種類の見た目既定」なので P10 の判定では style.toml。`[table]` 直下にフラットな
`head_typeface` を置き（`[table.head]` の副テーブルは作らない。#389 の `[page]` と同じ理由。既存の副テーブル
`[table.caption]` は共有 struct 型の再利用が理由であって、単一スカラーのために副テーブルは
作らない）、値は指定された `Typeface` を**そのまま**使う。2 つの選択肢を退けた:

- (a)「未指定なら `[text].typeface` を太字化して導出する」— 解決済み style 型の `Option` は
  「定数フォールバック」（`rule_color` の黒）と「単純継承」（`hyperref` の本文色）の 2 語義しか持たず、
  導出は第 3 の語義になる。兄弟の書体フィールドはすべて具体値 + リテラル既定で、
  `list.marker_typeface = serif` は「本文を sans にしてもマーカーは serif のまま」を既に許容している
- (b)「指定値を常に太字化する」— 非太字ヘッダが表現不能になり、`serif` と `serif_bold` が同じ結果になる
  （`$$` 不採用と同じ「同じ結果への 2 通りの書き方」）

既定は `serif_bold`。`\head` にオプションは足さない — 個別要素の書体変更には 12 装飾コマンド
（`\head{\sans{...}}`）が既にあり、同じ結果への第 2 の書き方を作らないため（P10 だけなら個の設定として
`\head[typeface=...]` も許されるが、言語内の逃げ道が先にある）。

#### 図・表キャプションの書体を style.toml へ（2026-08、#457）— P10

キャプションの書体も「図・表という種類の見た目既定」なので P10 の判定では style.toml。共有型 `CaptionStyle` に `typeface` を 1 つ置く形は #393 の「単一スカラーのために副テーブルを作らない」に
反しない — `[figure.caption]` / `[table.caption]` は既に共有 struct 由来で存在する副テーブルで、そこへ足す
ほうがフラット化（`[figure].caption_typeface`）より概念層が割れない。既定は `serif`。2 つを別の強度で落とした:

- (a) **恒久不採用** `\caption[typeface=...]` のソースオプション — #393 の `\head` と同型で、個別要素の
  書体変更には 12 装飾コマンド（`\caption{\sans{...}}`）という言語内の逃げ道が先にある
- (b) **見送り（恒久不採用ではない）** 番号部分と本文部分の書き分け — これは「同じ結果への 2 通りの
  書き方」には当たらない（「番号は太字・本文は標準」は本変更後も表現不能で、書き分け手段は厳密に表現力の
  増加。`$$` 不採用の論法は転用できない）。落とす根拠は「まず種類既定で足りないかを検討する」という段取りの
  ほうで、将来足すなら `number_typeface: Option<Typeface>`（未指定なら `typeface` を継承）が #393 の
  認める「単純継承」の語義そのままなので、いま `typeface` 1 つで入れることは障害にならない。再検討
  トリガーは「番号側だけ太字・スモールキャップスにしたい」という具体要求

#### 索引ページ番号の範囲表記は表記であって内容ではない（2026-09、#508）— P10, G3

索引エントリが指す出現ページの集合は内容で、`\index` マーカーの位置から一意に決まる。`3, 4, 5` と並べるか
`3–5` と畳むかはその集合の**表記**でしかないので、P10 の判定は「種類の見た目」→ style.toml
（`[index].collapse_page_ranges`、既定 `false`）。ソース側に畳み指示を持たせない（G3: ソースは内容のみ）。
区切り記号（en dash）と畳む閾値（3 ページ）は慣習として固定の定数で style へ出さない — 「変えたい」という
具体要求が来ていない段階でノブにすると、同じ結果への書き方だけが増える。

明示範囲マーカー（LaTeX の `|(` `|)` 相当）は**見送り（恒久不採用ではない）**。「ここから連続的に論じている」
は著者だけが知る内容の意味論で、機械的な連番畳み（表記）とは別物であり、表現力の増加にあたる。再検討
トリガーは「連続的に論じた範囲を明示したい」という具体要求で、採用時は P2 / P3 に適合する構文で設計する。

#### 索引の区分は照合順序から導き、ラベルは慣習の固定表にする（2026-09、#509）— P10, G3

索引エントリを五十音行・A–Z へ区分して見出しを挟むかは、索引という**種類**の見た目既定なので P10 の判定は
style.toml（`[index].group_headings`、既定 `false`。体裁は `group_font_size` / `group_top_margin` /
`group_bottom_margin`）。ソースは変更しない（G3）。

区分の導出は ICU の `AlphabeticIndex` と同じ「照合順序からの区間割り当て」方式を採る。かな正規化表（カタカナ→ひらがな・濁点除去・小書きの
通常化）や「ん」の特例といった個別規則を持たないのが要点で、区分とソートが同じ照合順序から出るため両者の
不整合が構造的に起きない。「がぎ」→ か 行、「ピアノ」→ は 行、「ん」始まり → わ 行はこの規則から自動的に
従う。ラベル区間の外（数字・記号始まりと、かなより後に照合される reading 無しの漢字語）は末尾 1 つの受け皿へ
統合する — ICU 本家の「索引の前後 2 箇所の受け皿」は採らない（読者には受け皿が 1 つのほうが単純）。

区分ラベル（「あ」「か」…と A–Z の 36 個）は言語慣習の固定表なので style へ出さない — 「変えたい」という
具体要求が来ていない段階でノブにすると、同じ結果への書き方だけが増える（#508 の区切り記号・閾値と同じ論法）。
受け皿の見出しだけは `group_other_label` で差し替えられ、既定が英語 `"Others"` なのは事例
「表示文字列の i18n は style.toml の明示指定のみ」に従う（日本語化は `group_other_label = "その他"` の上書き）。ラベル文字列の style 差し替えは
**見送り（恒久不採用ではない）**で、再検討トリガーは「この行ラベルを変えたい」という具体要求。

#### 数式中のソース空白は組版に出さない（2026-08、#86）— G3, P10

数式クラスに基づく自動スペーシングを入れると、著者が書いた空白と自動アキが二重になる。TeX と同じく数式
モードの空白は無視し、`$a+b$` と `$a + b$` を同じ出力にする。G3（内容が見た目から独立）に整合する — 記号
どうしのアキは「どう見せるか」であって内容ではないので、ソースの空白の有無で結果が変わってはならない。
アキ量（thin 3mu / medium 4mu / thick 5mu）は style.toml に出さず typeset の固定定数に
した — P10 の判定では「種類の既定」に見えるが、この 3 値は数式組版の慣習定数であり、種類ごとに差し替える
性質の値ではない。**見送り（恒久不採用ではない）**で、再検討トリガーは「アキ量を変えたい」という具体要求。
そのときは `[math.spacing]` として style.toml へ移す（明示アキのコマンドも同じ値に従う）。数式中に明示的なアキを
入れる手段は、P2 に従う通常のコマンドとして足した（#485 の事例）。
インライン数式の行分割点のペナルティ（`\binoppenalty` / `\relpenalty` 相当の 700 / 500、#171）も同じ理由で
コード定数とし、style.toml へは出さない。
`\text{...}` の引数は数式ではなく文章で、この規則の例外ではない（語と語の区切りは内容、記号どうしのアキは見た目 — #977）。

#### 段落・見出しの揃えは 4 値 1 キー（2026-10、#889）— P10, G1, P6

本文段落と見出しの揃えは「本文段落全部」「この見出しレベル全部」という種類の既定なので、P10 の判定では style.toml
（`[text].alignment` / `[heading.<level>].alignment`）。確定した判断は 3 点:

- **4 値 enum**: 両端揃えの有無と寄せる向きを別キーに分けず、`"justify"` / `"left"` / `"center"` / `"right"` の 1 キーにした。
  2 キーだと「両端揃え × 中央・右」に意味を与える（`text-align-last` 相当）か、組み合わせを検証で拒否するかを選ぶことになる。
  4 値ならその状態を表現できない（G1）。綴りは `[math.block].alignment` の `left` / `center` / `right` と揃う
- **見出しの単純継承**: `[heading.<level>].alignment` は未指定なら外側の揃え（既定では `[text].alignment`）に従う。#393 が
  認める「単純継承」の語義で、継承を明示する値（`"inherit"`）は未指定と同じ結果への第 2 の書き方になるので足さない。
  2 レイヤーマージには TOML から「未指定」へ戻す手段が無いので、レベル別既定はどのレベルも未指定に保つ（`qed_mark` と
  同じ制約）。具体値の既定を置きたくなったら、その時点で再検討する
- **字下げは揃えと独立**: `first_line_indent` は `"center"` / `"right"` でも行頭の内容として残す。揃えの値から字下げを
  決めると、#393 が退けた「導出」になる。字下げを消したい文書は `first_line_indent = "0pt"` と書く

種類ごとに揃えが決まっているもの（脚注本体・図表・タイトルページ・数式ブロック・表のセル・柱）は従わない。目次のエントリ行と
索引は `[toc]` / `[index]` の揃え（#905）に従い、`[text].alignment` に連動しない。目次の題目行だけは `[heading.section]` の体裁を
借りるので、その揃え（未指定なら `[text].alignment`）を通じて連動する。

#### コードブロックの行揃えは左固定（2026-10、#889）— P10, G3

verbatim のコードでは行どうしの桁の相対位置（字下げ）が内容なので（#448）、center / right を行ごとに当てると style.toml の
差し替えで内容が変わり、P10 の不変条件を破る。したがってコードブロックは `[text].alignment` に従わず左に固定し、ソースの
オプションも style キーも設けない（`\code{...}` は段落内の箱なので周囲の揃えに従う）。行の相対位置を保ったままブロック全体を
寄せる・字下げするのは種類の見た目なので**見送り（恒久不採用ではない）**とし、再検討トリガーは「コードブロック全体の配置を
変えたい」という具体要求。そのときは style.toml の `[code]` へ置く。

#### 目次・索引の行の揃えと、効かないキーの組み合わせの拒否（2026-10、#905）— P10, G1, P6

目次・索引の行の揃えは「目次の行全部」「索引の行全部」という種類の既定なので、P10 の判定では style.toml（`[toc].alignment` /
`[index].alignment` / `[index].title_alignment`）。目次・索引は生成物でソース上に対応する要素が無いので、ソースのオプションは
作らない。確定した判断は 5 点:

- **3 値で両端揃えを書けなくする**: 目次・索引の行は折り返さない 1 行で、両端揃えに意味が無い。4 値の `TextAlignment` を受けて
  検証で `justify` を落とすのではなく、`[math.block].alignment` と共有する 3 値（`left` / `center` / `right`）の型にして書けなく
  する（#889 の「組み合わせを検証で拒否するより表現できなくする」と同じ論法）
- **目次の題目は section 見出しに従う**: 目次の題目は既に `[heading.section]` から書体・サイズ・下余白を借りている。揃えだけを
  `[toc]` に置くと題目 1 行の見た目を決める場所が 2 つになる（G1）ので、`[heading.section].alignment`（未指定なら
  `[text].alignment`）に従わせ、キーを足さない。索引の題目は `[index]` が既に題目専用のキー（`title_font_size` 等）を平置きで
  持つので `title_alignment` を足す。区分見出しはエントリ列の一部として `alignment` に従う
- **揃えの基準は行の利用可能幅、字下げは残す**: 索引は段組みの 1 段の幅で寄せ、題目も 1 段目の中で寄る。目次の階層字下げは
  揃えから導出せず行頭の内容として残す（#889 の `first_line_indent` と同じ）。利用可能幅を超える行は寄せない
- **効かない組み合わせは拒否する**: 判定基準は「その値が、どの内容に対しても出力を変えない組み合わせだけを拒否する」（#904 の
  冗長判定「どの style.toml でも同じ結果になる書き方は冗長」をキーどうしの組み合わせへ延長したもの）。ページ番号を出す目次の行は
  内容によらず右端まで伸びるので、`[toc].alignment` が `left` 以外 × `show_page_numbers = true` は拒否する。ページ番号の有無と
  揃えは直交する 2 概念なので、#889 のように 1 キーへ畳んで表現不能にはしない（`entry_layout = "page_numbers" | "center" | …` は
  「center ならページ番号が消える」が字面から読めない）。同じ基準に当たる `leader` × `show_page_numbers = false` も、`leader` の
  既定をリーダー無しにしたうえで拒否する（#915）
- **見送り（恒久不採用ではない）**: 区分見出しだけを別の揃えにするキー（再検討トリガーは「区分見出しだけエントリと違う揃えに
  したい」という具体要求）と、目次の題目を `[heading.section]` から切り離して `[toc]` に題目専用の体裁キーを持たせること
  （再検討トリガーは「目次の題目だけ section 見出しと違う体裁にしたい」という具体要求）

#### 目次のリーダーの既定は無し（2026-10、#915）— P10, G1, P6

目次のリーダー（`[toc].leader`）はエントリ末尾とページ番号の間にだけ描くので、`show_page_numbers = false` のもとではどの内容に
対しても出力を変えない。#905 の基準をそのまま当ててこの組み合わせを拒否する。「目次の行全部のリーダー」は種類の既定なので
style.toml に置き、生成物なのでソースのオプションは作らない（#905 と同じ P10 判定）。確定した判断は 4 点:

- **従属するキーの既定は、支配するキーのどの値のもとでも有効にする**: 既定 `"."` は `show_page_numbers = false` のもとで効かず、
  対称に拒否するとページ番号なしの目次すべてに既定を打ち消す記述を強いる。既定を「無し」にすると両方の値で有効になる。ドットが
  欲しい文書が書く `leader = "."` は意図そのものの記述で、退けたのは「意味の無い既定を打ち消す記述」（`leader = ""` の必須化）のほう
- **1 キーへ畳まず検証で拒否する**: リーダーはページ番号に従属するので、#889 / #905 の「検証で拒否するより表現できなくする」に
  従えば畳むのが自然だが、状態は「番号なし / 番号のみ / 番号 + 単位文字列のリーダー」の直和になる。TOML では、単位文字列を別キーに
  持たせるとその間に効かない組み合わせが再発し、単位を固定の語にすると `…` などへ差し替えられず、語と任意の単位文字列を 1 キーに
  混ぜると語 `"none"` と単位文字列 `"none"` が字面で区別できず（G1）、サブテーブルの有無で表すと既定がページ番号ありなので消せない。
  表現できなくする手段が無いので検証へ落とす
- **明示的に書いた値だけを拒否する形は採らない**: 既定 `"."` を保って書かれた値だけを拒否するには「書かれたか」を区別する
  診断専用の層が要り（新しい型は不変条件を運ぶときだけ、という簡潔さの判定に反する）、解決後の値に意味の無い状態
  （番号なし + `"."`）が残る
- **「無し」の書き方は 1 つ**: `leader = ""` は空文字列として拒否する（`[theorems.<class>].qed_mark` と同じ）。リーダー無しは
  キーを書かないことだけで表す（G1）。空白だけのリーダーは、見た目上消えるかがフォント次第で style の検証時（フォント読込より前）
  には判定できないので拒否しない（**見送り（恒久不採用ではない）**。再検討トリガーは「不可視のリーダーが誤設定の原因になった」と
  いう具体報告で、採るならフォント読込後の検証として設計する）

proof の `qed_mark` の既定 `"□"` を TOML から無しへ戻せないことは本件の基準に当たらない（`qed_mark` にはどの内容に対しても効かない
組み合わせが無い）ので扱わない。**見送り（恒久不採用ではない）**で、再検討トリガーは「QED マークの無い proof を書きたい」という
具体要求。そのときは 2 レイヤーマージで `None` へ戻す書き方の問題として扱う。

### G1 適合例 — 同じ結果への書き方を増やさない

#### 表構文の再設計（LaTeX tabular の暗号性排除）— G1, P3

行は `\row{...}`・セル区切りは `&`・特殊なセルだけ `\cell[...]{...}` にエスカレート。列指定は
`columns=left center right` のフルスペルのみで `l/c/r` 略記は不採用、幅は `widths` へ分離（G1: 字面だけで
読める）。LaTeX `{c|l|r}` の `|` は廃止し、罫線は列指定と別管理・デフォルト罫線なし・横罫線は行属性
`\row[rule_above]`（P3）。ヘッダは `\head{}` 専用コマンド（改ページ時の自動再描画の基準）。改ページは
デフォルト可・`[breakable=false]` で禁止し、`longtable` 風の別環境は作らない（同じ結果への書き方を
増やさない）。互換要望が来ても略記・`|` は復活させない。

#### auto vs enabled はソースにマーカーがあるかで決まる（2026-07、#247）— G1, P10

巻末索引・書誌（`\cite`）はいずれも `enabled` フラグを持たず、ソースに対応マーカー（`\index` / `\cite`）が
1 個以上あるときだけ自動出力する。対して目次（`[toc].enabled`）はオプトイン方式 — 見出しは本文の構造から
常に存在し「目次を出すか」はソースから自明に決まらないため、明示フラグが必要。判定基準は「出力するかどうかが
ソースの記述（マーカーの有無）から一意に決まるか」（G1）。一意に決まるなら `enabled` を追加しない（同じ
結果への書き方を増やさない、`$$` 不採用と同じ理由）。巻末索引ページの体裁（`[index]`）自体は種類の既定
なので style.toml が持つ（P10 の通常の適用）。

#### `\code` は `\mono` の第 2 の書き方ではない（2026-08、#448）— G1

`\code{...}` / `code` 環境は「内容としてのコード」で本体が verbatim（字句挙動が違う）、`\mono`（12 装飾
コマンドの 1 つ）は「見た目の等幅」で本体は通常の活性テキスト。同じ結果への 2 通りの書き方ではなく（§2 の判定: `\code` は内容を名指す名前）、字句
挙動と将来のスタイルフック（ハイライト・行番号）が違う別物として定義する。ブロック本体は `\begin{code}`
直後の改行 1 個と `\end{code}` 直前の行末改行 1 個だけを落とす（ソースを読みやすくするための改行を出力に
持ち込まないため）。落とすのは 1 個ずつなので、続く空行は内容として残り、`\end{code}` を字下げすると直前が
改行ではなくなって空白だけの最終行が残る（G1: 規則が 1 つで、字面から結果が読める側を採る）。

#### 段落を寄せる環境 `flushleft` / `center` / `flushright`（2026-10、#904）— G1, P2, P7, P10

署名・日付・題辞のように文書中の特定の段落群を寄せるのは「この段落群」という個の設定なので、P10 の判定ではソースに書く。
種類の既定は `[text].alignment`（#889）が持ち、「style.toml に既定 + ソースで個別上書き」の型になる（`[item_gap=...]`、#157 と同型）。
効果範囲は環境本体で閉じ（P7）、`\raggedleft` / `\centering` のような宣言型は効果の終わりが構文から分からないので採らない。確定した判断は 4 点:

- **向きは環境名が持つ**: 向きを引数で選ぶ 1 つの環境にはしない。省けるオプション `[align=right]` にすると、省いた形は環境を
  書かないのと同じ結果になり、第 2 の書き方になる（G1）。必須にすると、評価に必須の情報は任意引数構文に置けない（#453）ので
  P2 の必須引数 `{right}` になり、#732 が再検討トリガーとする「必須引数を取る環境」にあたる。名前が指定を完結させる先例は
  12 装飾コマンド・`quote` / `quotation`・定理の 10 環境。環境名 `flushleft` / `flushright` と値 `left` / `right` の綴りの
  ずれは原則が決めない決めの問題で、LaTeX の名前を保つ（定理環境で平易な名前への改名を採らなかったのと同じ判断）
- **置き換えるのは `[text].alignment` 1 キーだけ**: 本体の中では `[text].alignment` を環境の向きに置き換えたものとして組む。
  `[text].alignment` が効く段落（本文・リスト項目・引用・定理）と、レベルに揃えを指定していない見出し（単純継承）は環境の向きに
  寄る。揃えが種類で決まっているもの（レベルに揃えを指定した見出し・図表・数式ブロック・表のセル・コードブロック）と、本文の外で
  組む脚注本体は変わらない。入れ子では最も内側が効く。環境は上下の余白も、字下げの特例も足さない
- **既定と同じ結果になる環境は冗長ではない**: `[text].alignment = "left"` の文書の `flushleft` は既定と同じ結果になる。しかし
  §4 が冗長と判定するのは「どの style.toml でも同じ結果になる」書き方（`$$`、#393 (b)）である。寄せ環境は style.toml に
  関係なく向きを固定できる唯一の手段で、厳密に表現力を増やす（#457 (b) と同じ判定）。P10 の不変条件「同じソース + 別の
  style.toml でも個別指定は残る」も、これを必要とする
- **インライン形は恒久不採用、両端揃えの環境は見送り**: 段落 1 つを寄せるインラインコマンド形（`\flushright{...}`）は、同じ結果を
  得る言語内の手段（寄せ環境）が先にあるので**恒久不採用**（#393 の `\head` オプション、#457 (a) と同じ判断）。両端揃えへ戻す
  環境は冗長ではない（既定が `"center"` / `"right"` の文書では結果が変わる）。それでも、まず種類の既定で足りるかを検討する
  段取りと、具体要求が無いことから**見送り（恒久不採用ではない）**とする。再検討トリガーは「既定を `"center"` / `"right"` に
  した文書で、一部の段落だけ両端揃えにしたい」という具体要求（#457 (b) と同じ型）。寄せ環境の上下余白を style.toml で設定する
  口も**見送り**で、再検討トリガーは「寄せ環境の前後だけアキを変えたい」という具体要求
