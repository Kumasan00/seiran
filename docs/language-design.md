# Seiran 言語設計原則

Seiran の言語（`.sei` ソースの構文・コマンド・環境・設定ファイルの役割分担）を設計するときの
規範を定める。新コマンド・新環境・新オプション・新スタイルフィールドの設計判断は、
必ずこの文書の目的と原則に照らして行う。

構成は「前提（スコープ） → 目的（3 つ） → 原則（10 個、各原則がどの目的に仕えるか明記） →
判断事例集」。原則は目的の手段であり、原則と欲しい機能が衝突したときは
例外を継ぎ足すのではなく、目的に照らして原則側の改訂も検討する。

## 1. 前提（スコープ）

Seiran は **LaTeX の主要機能を組み込みで提供する汎用組版言語**である。

- 機能はコアが持つ。マクロ・パッケージ機構で機能を後付けする設計にしない
- LaTeX 互換層は作らない。TikZ のような埋め込みプログラミング言語も採用しない
- ユーザ拡張は将来の `\define` メタコマンド + `.seiran` ファイルに限定する
  （固定引数の新コマンド定義。プラグイン機構・スタイル継承は持たない）
- `\documentclass` 相当のクラス概念は導入しない

原則はすべてこの前提の内側で効く。「その機能を作るか」はこの前提が決め、
「作るならどう作るか」を以下の目的と原則が決める。

## 2. 目的

**読み手にも書き手にも曖昧さのない組版言語。** 3 つに分解する。

- **G1. 一意に読める** — ソースのどの箇所も、離れた場所の定義・実行状態・カテゴリコードに
  依存せず、字面だけで構造が一意に決まる。
- **G2. 効果が閉じる** — あらゆる指定の効果範囲が構文上で閉じており、書いた場所から見える。
  「いつ終わるか不明」な状態を作らない。
- **G3. 内容が見た目から独立** — ソースは内容のみ。同じソースに別の style.toml を当てれば、
  同じ内容の別の見た目が出る。

「同じ結果を得る書き方は一つ」（`$$` と `\[` を併存させない等）は独立の目的とせず、
各原則の適合例として扱う。

## 3. 原則

### P1. トークン規則は固定（G1）

字句規則は言語が固定し、ユーザは変更できない。カテゴリコードは存在しない。
コメントは `//`（`%` は将来の剰余演算子に予約）。特殊文字はエスケープ必須で、
文脈によって役割が変わる文字を作らない。

コードブロック（verbatim、#447）は「固定構文で入る固定の字句モード」であり、
ユーザによる字句規則の変更ではない。P1 と両立する。

### P2. 引数構文（G1）

引数を取る構文の必須引数は `{}` で明示し、個数・順序は構文ごとに固定する。
対象はコマンドに限らず、数式の上付き `^` / 下付き `_` も含む。
`\section Title` は不可で `\section{Title}` のみ、`$x^2$` は不可で `$x^{2}$` のみ。
コマンド名は英数字始まり・英数字続きで、英数字以外の文字で終端する。

### P3. オプション引数は名前付きのみ（G1）

オプションは `[key=value, ...]` の名前付きのみで、コマンド名／環境名の直後に 1 組だけ置ける。
順序自由・キー重複はエラー。bool 値は `key` 単独（`=true` 省略）を認める。
LaTeX の `\parbox[c][3cm]` のような位置依存オプションは作らない。

値は宣言済みスキーマ（String / Bool / Number / Length / Color）で検証する
（`frontend::evaluator::opt_args`）。実例: `\image[width=5cm, dpi=300]`、
equation 環境の `[label=eq1, numbered=false]`、`\cell[span=2]`、`\row[rule_above]`、
theorem 環境の `[title=...]`。

### P4. `{}` の意味は 2 つだけ（G1）

`{}` は「引数の境界」（コマンド・`^` / `_` など引数を取る構文）と「数式内のグループ化」のみ。
裸の `{...}` は構文エラーとする。

### P5. 数式モード境界の単純化（G1）

インライン数式は `$...$` のみ。ディスプレイ数式は数式環境（equation / align 等）のみ。
`$$...$$` と `\[...\]` は不採用（同じ結果への書き方を増やさない）。

### P6. 未知は拒否（G1）

未知のコマンド・環境・数式コマンド・カウンタ名・オプションキーは、静かに無視したり
フォールバックしたりせずエラーにする。環境本体に書ける要素は許可リスト方式。
設定ファイルも `deny_unknown_fields` で同じ方針を貫く。

推測で処理を続けないことで「書いたものがどう解釈されたか」の曖昧さを消す。

### P7. 効果範囲の構文的閉包（G2）

コマンド・環境の効果が及ぶ範囲は、構文だけから一意に決まらなければならない。
範囲は次のいずれかで閉じる。

- (a) 自身の引数（例: `\bold{...}`）
- (b) 環境本体（例: `\begin{quote}...\end{quote}`）
- (c) 構造上固定の単位（例: align の行末 `\notag` ＝その行のみ・置ける位置も一意）

ソースを読み進めないと終端が分からない指定は作らない。非適合例: LaTeX の `\bfseries`。

宣言型か引数型かは手段の選択にすぎない。新コマンドを宣言型にしたい場合は
「(a)(b)(c) のどれで閉じるか・置ける位置が一意か」を判定し、閉じないなら引数型か環境にする。

### P8. マクロ置換なし（G1, G2）

テキスト置換機構は提供しない（`\newcommand` 相当なし）。将来の `\define` は
「固定引数の新コマンド定義」であり置換ではなく、P2 / P3 の引数規則に従う。
`{}` 引数は自己区切りなので、定義を知らなくても構文解析は常に一意に決まる。

### P9. プログラミング機能なし（G1, G2）

計算・条件分岐・ループは提供しない。ソースの評価結果が入力以外に依存しない。

### P10. 内容と見た目の分離 — 線引きは「種類 vs 個」（G3）

- **種類・文書全体の既定はソースに書けない。** 「見出し全部」「表キャプション全部」
  「本文フォント」のような種類（クラス）単位の見た目デフォルトは style.toml、
  物理・実体・メタデータは config.toml に置く。ソースに書けば文書全体へ開いた効果になり
  P7 とも矛盾する。プリアンブル相当の禁止・クラス概念の不採用はここから導出される
- **個別要素の設定はソースに書ける。** 効果がそのコマンド・環境 1 つに閉じる限り、
  抽象的な種類（`[float=top]`）も具体的な数値（`\image[width=5cm]`）も可。
  オプション引数（P3）がその受け皿
- **両方要るものは「style.toml / config.toml に既定 + ソースで個別上書き」** の型にする。
  実例: 画像 DPI（config.toml `[image].max_dpi` + `\image[dpi=...]`）。
  フロート挙動（style.toml の既定 + `[float=...]`、#111）も同型だが実装は未着手

**判定テスト**: 「これは 1 要素の設定か、種類の既定か？」
個 → ソースのオプション。種類 → style.toml（見た目）/ config.toml（物理・実体）。

**不変条件**: 同じソース + 別の style.toml ＝ 同じ内容・同じ個別指定のまま、
種類既定だけが変わる。style.toml へ新フィールドを足すときの判断基準
「同じ本文 + 同じ用紙で style.toml だけ差し替えて見た目を変えられる」はこの不変条件の言い換え。

**基準と機能判断の分離**: P10 が決めるのは「その指定をどこに置くか」だけ。
「そのオプションを提供するか」は機能ごとの判断で、まず種類既定（style.toml）で
足りないかを検討してから個別オプションを設ける。

以下の事例表は判定の索引（経緯・根拠の全文は §4 判断事例集）。

| 事例 | 判定 | 根拠 |
| --- | --- | --- |
| 12 装飾コマンド・`\color` | ソース可 | 個別要素（引数に閉じる）。書体の実体は config.toml の 19 種別が決める |
| `\caption` の出現位置で Top / Bottom | ソース可 | 「ソースの順序＝内容の順序」の帰結。スタイル側に位置指定は持たない |
| `[float=top]`（#111、未実装） | ソース可 | 個別要素の配置指定。既定挙動は style.toml のフロートデフォルト（実装も #111） |
| `\cell[span=N]` / rowspan（#112、rowspan は未実装）/ 開始番号 `[start=N]`（#156） | ソース可 | 表の構造・列挙の番号は内容そのもの |
| `\item` の個別マーカー上書き（#155） | ソース可 | 個別要素の設定。段別マーカーの既定は style.toml（#159） |
| リスト項目間隔の上書き `[item_gap=N]` / `\item[item_gap=N]`（#157） | ソース可 | 個別要素・環境単位の設定。項目間隔の既定は style.toml（`list.item_margin_bottom`） |
| ソースで本文フォント・全見出し書式を変える類 | 不可 | 種類・文書全体の既定。style.toml へ |
| ページ余白（`[page]` の `margin_*`、#389） | style.toml | 用紙の物理量ではなく「用紙のどこを本文領域にするか」＝見た目。用紙寸法（`[pdf]` の width / height）は実体なので config.toml に残す |

## 4. 判断事例集

過去の確定判断を該当原則に紐づけて**全文で**記録する正典。今後の設計判断もここに追記する。
P10 の事例表（§3）は判定の索引で、相互の参照は行番号ではなく issue 番号・事例名で行う。
エントリに書くのは判定・原則への紐付け・設計上の根拠までで、実装パターンの記述は
該当 issue / `docs/architecture.md` に置く。

- **ページ余白を config.toml から style.toml へ（#389）** — 余白は「用紙という実体の物理量」ではなく
  「用紙をどう使うか」なので P10 の判定では種類の既定＝見た目。`[page]` に
  `margin_top` / `margin_bottom` / `margin_left` / `margin_right` をフラットに置き（`[page.margin]` の
  副テーブルは作らない）、用紙寸法は `config.toml` の `[pdf]` に残す。これで不変条件
  「同じ本文 + 同じ用紙で style.toml だけ差し替えて見た目を変えられる」が版面の広さにも成り立つ。
  旧 `pdf.margin_*` は未知キーとしてエラーにする（静かに既定余白へ切り替わるとレイアウトが黙って
  変わるため。意図的な破壊的変更）

- **表ヘッダ行の書体を style.toml へ（#393）** — `\head{}` セルの書体は「表という種類の見た目既定」
  なので P10 の判定では style.toml。`[table]` 直下にフラットな `head_font_kind` を置き
  （`[table.head]` の副テーブルは作らない。#389 の `[page]` と同じ理由。既存の副テーブル
  `[table.caption]` / `[math.script]` は共有 struct 型の再利用が理由であって、単一スカラーのために
  副テーブルは作らない）、値は指定された `FontKind` を**そのまま**使う。2 つの選択肢を退けた:
  (a)「未指定なら `[text].font_kind` を太字化して導出する」— 解決済み style 型の `Option` は
  「定数フォールバック」（`rule_color` の黒）と「単純継承」（`hyperref` の本文色）の 2 語義しか
  持たず、導出は第 3 の語義になる。兄弟のフォント種別フィールドはすべて具体値 + リテラル既定で、
  `list.marker_font_kind = serif` は「本文を sans にしてもマーカーは serif のまま」を既に許容している。
  (b)「指定値を常に太字化する」— 非太字ヘッダが表現不能になり、`serif` と `serif_bold` が同じ結果に
  なる（`$$` 不採用と同じ「同じ結果への 2 通りの書き方」）。既定は `serif_bold` で、`[text].font_kind`
  を既定以外にしているプロジェクトではヘッダ書体が変わる意図的破壊（#389 と同種）。
  `\head` にオプションは足さない — 個別要素の書体変更には 12 装飾コマンド（`\head{\sans{...}}`）が
  既にあり、同じ結果への第 2 の書き方を作らないため（P10 だけなら個の設定として
  `\head[font_kind=...]` も許されるが、言語内の逃げ道が先にある）

- **図・表キャプションの書体を style.toml へ（#457）** — キャプションの書体も「図・表という種類の
  見た目既定」なので P10 の判定では style.toml。現状の `FontKind::Serif` ハードコードは種類既定が
  typeset のコード（`build_caption`）に埋まっていた状態なので、この変更は新設というより是正にあたる。
  共有型 `CaptionStyle` に `font_kind` を 1 つ置く形は #393 の「単一スカラーのために副テーブルを
  作らない」に反しない — `[figure.caption]` / `[table.caption]` は既に共有 struct 由来で存在する
  副テーブルで、そこへ足すほうがフラット化（`[figure].caption_font_kind`）より概念層が割れない。
  既定は現行の固定値そのものの `serif` なので、#393 と違い既存プロジェクトの出力は変わらない。
  2 つを別の強度で落とした:
  (a) **恒久不採用** `\caption[font_kind=...]` のソースオプション — #393 の `\head` と同型で、
  個別要素の書体変更には 12 装飾コマンド（`\caption{\sans{...}}`）という言語内の逃げ道が先にある。
  (b) **見送り（恒久不採用ではない）** 番号部分と本文部分の書き分け — これは「同じ結果への 2 通りの
  書き方」には当たらない（「番号は太字・本文は標準」は本変更後も表現不能で、書き分け手段は厳密に
  表現力の増加。`$$` 不採用の論法は転用できない）。落とす根拠は「まず種類既定で足りないかを検討する」
  という段取りのほうで、将来足すなら `number_font_kind: Option<FontKind>`（未指定なら `font_kind` を
  継承）が #393 の認める「単純継承」の語義そのままなので、いま `font_kind` 1 つで入れることは
  障害にならない。再検討トリガーは「番号側だけ太字・スモールキャップスにしたい」という具体要求。

- **数式中のソース空白は組版に出さない（#86）** — 数式クラスに基づく自動スペーシングを入れると、
  著者が書いた空白と自動アキが二重になる。TeX と同じく数式モードの空白は無視し、`$a+b$` と
  `$a + b$` を同じ出力にする。G3（内容が見た目から独立）に整合する — 記号どうしのアキは
  「どう見せるか」であって内容ではないので、ソースの空白の有無で結果が変わってはならない。
  空白除去は typeset 側（`typeset::lowering::math::spacing`）で行い、HIR には空白を残す
  （HIR は著者が書いたものの表現であるという `document` の位置づけを保つため）。
  アキ量（thin 3mu / medium 4mu / thick 5mu）は style.toml に出さず typeset の固定定数にした —
  P10 の判定では「種類の既定」に見えるが、この 3 値は数式組版の慣習定数であり、種類ごとに
  差し替える性質の値ではない。**見送り（恒久不採用ではない）**で、再検討トリガーは
  「アキ量を変えたい」という具体要求。そのときは `[math.spacing]` として style.toml へ移す。
  この変更で数式中に明示的なアキを入れる手段が無くなるため、`\thinspace` / `\quad` 相当の
  数式スペーシングコマンドは別途検討する（P2 に従う通常のコマンドとして足せるので、
  本判断の障害にはならない）

- **数式スクリプトの内容は `{...}` のみ（2026-08、#486）** — 上付き `^` / 下付き `_` の内容は
  波括弧グループに限り、`$x^2$` も `$x^\alpha$` も構文エラー（`frontend::parse::script_requires_group`）
  にする。裸の内容を許すと範囲が字句のトークン境界で決まり、`$x^2=y$` は `x²=y`、`$x^2+y$` は
  `x^(2+y)` と、後続の区切り文字の種類でスコープが変わってしまう（`=` `,` は構造文字でトークンが
  切れるが `+` `-` `(` は切れない）。字面から範囲が読めないので G1 に反する。採用形は P2
  「必須引数は `{}` で明示」の直接適用で、#453 の判定テスト（その値なしでハンドラが成功しうるか）も
  「`$x^$` は既にエラー ＝ 必須引数」を返す。これに伴い P2 の見出しを「コマンド構文」から
  「引数構文」へ広げ、P4 の意味 1 を「引数の境界」と一般化した（`{}` の意味は 2 つのまま）。
  2 案を落とした:
  (a) **恒久不採用** LaTeX と同じ「1 文字で閉じる」 — 言語内で唯一「引数の終端が可視のデリミタでなく
  文字数で決まる」構文になり、`{}` / `[]` / `$` / `\end{}` で閉じる他のすべての引数と規則が割れる。
  さらに `+` `-` が構造文字でない現状の字句規則のもとでは `$x^-1$` が `x⁻1`（マイナス 1 乗ではない）に
  **診断なしで**化け、現行の不具合より退行するケースが出る。「1 文字」を書記素クラスタで定義する
  字句概念の追加も要る。
  (b) **恒久不採用** 裸のコマンド 1 個（`$x^\alpha$`）だけ許す — `$x^{\alpha}$` と字句挙動も出力も
  同一の第 2 の綴りになる（`$$` 不採用・`\pagebreak` エイリアス不採用と同じ理由。`\code` と `\mono` の
  ように別物として併存させる根拠＝字句挙動の差が無い）。
  既存の `.sei` が書き換えなしでは通らなくなる意図的な破壊的変更で、#389 / #393 / #453 と同種。
  移行は `x^2` → `x^{2}` の機械置換で済み、`{...}` を挟んでも HIR は `Superscript(Group([...]))` に
  なるだけで組版結果は変わらない（既存 golden は 1 本も動かない）

- **`\notag`（P7 を「宣言型は原則避ける（例外あり）」から構文的閉包へ改めた契機）** — align / gather の
  行末マーカー。効果はその行のみ・置ける位置も行末で一意（P7 (c) 適合）。旧原則では例外扱いだったが、
  現行 P7 では例外ではなく適合例
- **`\textbf` 系の削除と 12 装飾コマンド** — `\serif` / `\bold` / `\italic` / `\bolditalic` /
  `\sans` / `\sansbold` / `\sansitalic` / `\sansbolditalic` / `\mono` / `\monobold` /
  `\monoitalic` / `\monobolditalic`（3 ファミリ × 4 スタイル、内側が完全上書き）。
  引数型で閉じ（P7）、ソースは「太字という種類」だけを書き実体フォントは config.toml が決める（P10）。
  **拡張規則**: 新しい装飾は合成可能なモディファイアではなく「完全な書体を 1 コマンドで指定する」
  形で追加する（当初の `\textbf` / `\emph` 方式は親スタイルとの合成が破綻して廃止した経緯）。
  `\color`（#31）は書体と直交する属性なので装飾の完全上書きとは別系統で、上書きではなく合成される
  （`\bold{\color[...]{x}}` も逆順も両方効く）。コマンド名は `\textcolor` ではなく `\color`
  （`\bold` / `\sans` と同じ text 接頭辞なし規則）
- **`$$` / `\[` 不採用** — P5。同じ結果への書き方を増やさない
- **エラー厳格化（2026-06）** — 括弧等の特殊文字はエスケープ必須（P1）、
  未知の数式コマンドはエラー・環境本体は許可リスト方式（P6）。個別の確定判断:
  裸の `[` はテキスト・数式ともエラー（stray `]` が既にエラーだったことと対称。区間表記は
  `\[0,1\]` と書く。LaTeX 互換に読み替えるレンダリング案は不採用）。閉じない `$` はエラーで
  通貨表記は `\$` 必須。未知の数式コマンドのエラー化に伴い、リテラル表示への暗黙復帰は IR ごと
  削除（P6: 静かなフォールバックを残さない）。インライン文脈（見出しタイトル・キャプション・
  装飾引数）でも未知コマンド・ブロック要素・環境・空行はエラー。数式外の `_` `^` `&` は本文と
  同じプレーンテキスト扱い（エラーではない）。`label=` の重複はエラー。コマンドの必須引数は
  外側文脈のパースモードを継承し（`\frac{x^{2}}{y}` の `^` を構造化するため）、任意引数 `[...]` は
  常に Text モード（key=value 用）
- **`\input` 不採用** — ソースの合成は config.toml の `sources` で行う。
  どのファイルをどの順で束ねるかは「実体」であり config の管轄（P10）
- **キャプション位置はソース出現順で決定** — `\caption` が本体より前なら Top、後なら Bottom。
  ソースの順序＝内容の順序（P10 の事例）
- **数式番号の 3 系統（tag / number / ref）** — 式の横に出す tag は `[math.block].tag_format`、
  採番書式・参照書式は `[counters.equation]`。いずれも種類既定なので style.toml（P10）
- **`\pagebreak`（2026-07）** — その位置で強制改ページするマーカー。引数なし・任意引数なしで、
  効果が 1 点に閉じ置ける位置も一意なので P7 (c) 適合（`\notag` と同型）。エイリアス（`\newpage` /
  `\clearpage`）と強度オプション（`[weight=0-4]`）は不採用 — 同じ結果への書き方を増やさない
  （`$$` 不採用と同じ理由）。style.toml `[heading].page_break_before` / `page_break_after` が
  「見出しという種類の既定」、`\pagebreak` が「この 1 点」の個別指定で P10 適合。段落の途中・
  quote / theorem / list 項目の本体に書けるのは許容（P6 は未知のコマンド・キーを拒否する原則で
  あって位置の妥当性を裁く原則ではない。同じ挙動の先例が `\space{N}`）。内容（本文または確定脚注）を
  挟まない位置（文書先頭・連続・末尾）では冪等な no-op として畳む — 「実際にページを送るか」は
  組版結果に依存しフロントエンドでは判定できず、break 段でエラーにすると span を失って診断が劣化
  するため。インライン文脈（脚注・表セル・キャプション）はエラーで拒否する（P6）
- **`enumerate[start=N]`（2026-07、#156）** — 開始番号は P10 の事例表（#156 の行）で既に「ソース可」と
  判定済み（列挙の番号は内容そのもの）。`itemize`（unordered）には無意味なので許可せず、
  専用の禁止ロジックは持たず未知キーとして拒否する（P6 の直接適用）。採番は環境呼び出しごとに
  ローカルな値で、ネストした `enumerate[start=N]` は外側・兄弟リストの採番に影響しない
- **リスト項目間隔の上書き `item_gap`（2026-07、#157）** — P10 の事例表（#157 の行）で「ソース可」と
  判定済み（項目間隔は個別要素・環境単位の設定、既定は style.toml）。環境単位 `[item_gap=N]` と
  項目単位 `\item[item_gap=N]` の両方を認め、優先順位は `\item` 個別 > 環境単位 > style.toml 既定。
  ネストしたリストへは伝播しない（#156 の `start` と同型）
- **auto vs enabled はソースにマーカーがあるかで決まる（2026-07、#247）** — 巻末索引・書誌
  （`\cite`）はいずれも `enabled` フラグを持たず、ソースに対応マーカー（`\index` / `\cite`）が
  1 個以上あるときだけ自動出力する。対して目次（`[toc].enabled`）はオプトイン方式— 見出しは
  本文の構造から常に存在し「目次を出すか」はソースから自明に決まらないため、明示フラグが必要。
  判定基準は「出力するかどうかがソースの記述（マーカーの有無）から一意に決まるか」（G1）。
  一意に決まるなら `enabled` を追加しない（同じ結果への書き方を増やさない、`$$` 不採用と同じ理由）。
  巻末索引ページの体裁（`[index]`）自体は種類の既定なので style.toml が持つ（P10 の通常の適用）
- **定理環境は 10 種固定 + style.toml 宣言（2026-06、#52-54）** — amsthm の `\newtheorem` は
  マクロ定義そのもので P8 と矛盾するため、定理クラスは style.toml で宣言しソースは環境名で
  参照する。環境名は amsthm 標準 10 種（theorem / lemma / proposition / corollary / definition /
  axiom / example / remark / claim / proof）で固定し、平易化リネーム（remark→note 等）は不採用。
  proof のみ無採番で QED マークを自動配置。証明は独立環境で直前の定理との暗黙紐付けはせず、
  明示リンクは `[of=...]` のみ（G1: 関係が字面から一意）。カウンタ共有は `counter` フィールドへの
  同名指定（LaTeX `\newtheorem{lemma}[theorem]` の第 2 引数の明示化）、リセットは見出しカウンタの
  増加時のみ（上位リセットでは戻さない。LaTeX 準拠）。番号書式は "1" / "i" 等の番号スタイルでは
  なくテンプレート文字列（`number_format = "{n}"` / `"{chapter}.{n}"`、counter の `number_format` と同形）。
  `\ref` の表示は `"{display_name} {number}"` 固定で、定理クラスは ref_format フィールドを
  持たない。ユーザ独自クラスは Tier 2
- **表構文の再設計（LaTeX tabular の暗号性排除）** — 行は `\row{...}`・セル区切りは `&`・特殊な
  セルだけ `\cell[...]{...}` にエスカレート。列指定は `columns="left center right"` のフルスペル
  のみで `l/c/r` 略記は不採用、幅は `widths` へ分離（G1: 字面だけで読める）。LaTeX `{c|l|r}` の
  `|` は廃止し、罫線は列指定と別管理・デフォルト罫線なし・横罫線は行属性 `\row[rule_above]`
  （P3）。ヘッダは `\head{}` 専用コマンド（改ページ時の自動再描画の基準）。改ページはデフォルト
  可・`[breakable=false]` で禁止し、`longtable` 風の別環境は作らない（同じ結果への書き方を
  増やさない）。互換要望が来ても略記・`|` は復活させない
- **`\define` のスコープ（Tier 2）** — 実装は Tier 2 まで行わない（MVP で評価器を複雑化させない）。
  対象はコマンドのみで、ユーザ定義環境はサポートしない（環境は前後処理が必要で固定引数の
  コマンド定義では表現できず、P8 の範囲を環境へ広げない。必要が出たら将来検討）。定義の
  置き場所は専用の `.seiran` ファイル（§1。ソース構文を流用して frontend の syntax を再利用する。
  TOML 内蔵は `\\` の二重エスケープが要るため不採用）で、config.toml の `commands_path` で指定
  する（P10: どの定義を読むかは実体）。2026-05 当初の「純テキスト置換 + 遅延展開」設計は P8 で
  無効 — 置換前提の実装スケッチ（MacroRegistry・再評価・循環検出）には従わない
- **表示文字列の i18n は style.toml の明示指定のみ** — 既定は英語（"Theorem" / "Figure" /
  "Table" 等）で、`[counters.*].display_name` 等の上書きで日本語化する。内蔵 locale（`ja` / `en`）
  の切替スイッチは設けない — 表示文字列は「種類の既定」で style.toml の管轄そのものであり
  （P10）、切替スイッチは同じ結果への第 2 の書き方になる。ハイフネーション・禁則の言語は
  フォントという実体に付く属性なので config.toml（P10）
- **verbatim 引数のブレースバランス走査は P4 の「引数境界」（2026-08、#447）** — verbatim 宣言された
  コマンドの必須引数は、対応の取れた `{}` を本体に含め対応しない `}` で終端する走査で読む。これは
  `{}` の意味 1「コマンドの引数の境界」の解釈であって第 3 の意味を作らない（P4 は 2 つのままで、
  例外を継ぎ足していない）。終端規則は全 verbatim 引数で統一しコマンドごとに変えない（G1: 字面だけで
  どこまでが引数か一意に読める）。バランスしないブレースを含む内容は verbatim 環境（ブロック）へ
  逃がす — 言語内に閉じた逃げ道があるので、`\verb|...|` 式の可変デリミタ（P2 違反）は要らない。
  ブロック側の終端は `\end{<環境名>}` の正確なバイト列一致 1 個だけで、`\end {code}` のような変形は
  一致せず、本体内の `\begin{<環境名>}` も計数しない。未終端はどちらもエラー（P6。「閉じない `$` は
  エラー」と同型）

- **引数のパースモード解決順 — レジストリ宣言が外側文脈の継承に優先する（2026-08、#447）** —
  「エラー厳格化（2026-06）」が定めた「コマンドの必須引数は外側文脈のパースモードを継承／任意引数は
  常に Text」に第 3 のケースを足す。verbatim を宣言したコマンドの必須引数は、外側が Text でも Math でも
  レジストリの宣言が勝って生読みになる（数式内の `\url` が `//` をそのまま書けるのはこの順序による。#236）。
  宣言できるのは frontend のレジストリだけで、ユーザは変更できず、将来の `\define` も verbatim 引数
  モードを宣言できない（P1 ガード: 字句規則をユーザに開かない）。継承のほうを既定に残すのは、
  `\frac{x^{2}}{y}` の `^` を構造化するという 2026-06 の理由がそのまま生きているため

- **`\code` は `\mono` の第 2 の書き方ではない（2026-08、#448）** — `\code{...}` / `code` 環境は
  「内容としてのコード」で本体が verbatim（字句挙動が違う）、`\mono`（12 装飾コマンドの 1 つ）は
  「見た目の等幅」で本体は通常の活性テキスト。同じ結果への 2 通りの書き方ではなく、字句挙動と
  将来のスタイルフック（ハイライト・行番号）が違う別物として定義する。ブロック本体は
  `\begin{code}` 直後の改行 1 個と `\end{code}` 直前の行末改行 1 個だけを落とす（ソースを読みやすく
  するための改行を出力に持ち込まないため）。落とすのは 1 個ずつなので、続く空行は内容として残り、
  `\end{code}` を字下げすると直前が改行ではなくなって空白だけの最終行が残る（G1: 規則が 1 つで、
  字面から結果が読める側を採る）

- **評価器にとって必須の情報を任意引数構文に置かない（2026-08、#453）** — `\href` のリンク先は
  `[url=...]` という任意引数値だったが、無ければ引数不足で落ちる ＝ 評価器にとっては必須だった。
  P2「必須引数は `{}` で明示し、個数・順序はコマンドごとに固定する」が要求する形になっていない
  状態なので、`\href{リンク先}{表示テキスト}` の 2 必須引数へ移す（P3 は `[key=value]` という
  字面の規則で、必須のものを任意引数に置いてよいとは言っていない ＝ 衝突していたのは P2 の側）。
  判定は「ハンドラがその値なしで成功しうるか」— 成功しえないなら必須引数、既定値を持って成功
  しうるなら任意引数。どちらの引数を第 1 にするかを裁く原則は無いので決めの問題として固定し、
  verbatim な側（リンク先）を先頭に置く（読み手が「ここから生読み」を先に知れる）。第 2 引数を
  省略したときのフォールバック（表示テキスト＝リンク先）は恒久的に足さない — それは `\href{U}` を
  `\url{U}` の第 2 の綴りにしてしまう（`\code` と `\mono` の判定と同型）

- **verbatim の終端文字を選ぶ根拠は「その文字が対象言語の文法で元々不正か」（2026-08、#453）** —
  verbatim はエスケープを持たず終端規則 1 個だけで成立するので、終端に選んだ文字は対象言語で
  書けなくなる。`\url` / `\href` のリンク先で `}` を終端に選べたのは、`{` `}` が RFC 3986 の
  reserved にも unreserved にも属さず URI 中では元々パーセントエンコードが必須だから ＝ 採用コストが
  ゼロだったため。この論拠は転用可否を判定する道具であって、verbatim 一般の許可証ではない。
  実際、任意引数値の verbatim 化（`\href[url=...]` を生読みする案）はこの判定で落ちた — 終端候補の
  `,` は RFC 3986 の sub-delim、`]` は IPv6 リテラルホストで合法なので、どちらを選んでもその文字を
  含む URL が言語内で書けなくなる。加えてブレースの場合と違い、オプション値には「ブロック環境へ
  逃がす」ような言語内の逃げ道が無い

- **数式レイアウト定数は本来フォント実体（OpenType MATH テーブル）由来** — 上付き下付きの
  シフト量・縮小率等を style.toml が持つのは MATH テーブル未対応（#91）の間の代用。P10 の判定
  ではこれらは「見た目の種類既定」ではなくフォントの実体に属する値で、MATH 対応後は自動取得へ
  寄せる（設定値は非対応フォント用フォールバックに退く）
